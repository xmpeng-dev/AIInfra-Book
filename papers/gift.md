## 一、问题分析 (Problem Analysis)

### 1.1 研究背景 (Research Background)

**领域现状**：

- 梯度通信是分布式 LLM 预训练的主要扩展瓶颈。论文引用的量化锚点：**GPT-8.3B 在 128×A100 上，通信占整体预训练时间的 40%**（Optimus-CC，ASPLOS'23）。
- 降低通信量最直接的手段是降低梯度表示的位宽——省下的每一 bit 直接按比例转化为带宽消耗的下降。
- **NCCL 2.24（2025 年初）加入了原生 FP8（e4m3 / e5m2）数据类型支持**，FP8 归约仅在 Hopper 及更新架构上启用。这是 GIFT 这类"直接用 FP8 跑 collective"的工作在工程上成为可能的前提。
- 现有 FP8 训练系统（FP8-LM、COAT）走的是**整体量化**路线：不只量化梯度，还量化权重、激活、优化器状态。
- 互联带宽的增长速度慢于算力，通信占比长期看只会上升。

**核心挑战**：

1. **现有低精度方法都在欧氏坐标里做缩放与量化**，而梯度是高度各向异性的：同一个标量 scale 要同时覆盖幅值差异极大的方向，大方差方向主导了 scale，小方差方向承受相对更大的失真。
2. **整体量化方案没法隔离梯度的贡献**。FP8-LM 和 COAT 都同时动了多个部件，无法回答"单独把梯度降到 FP8 值不值"。
3. **现有方法的模型质量说服力不足**（这是论文自己点的）：FP8-LM 在 10 个下游任务里有 7 个差于基线；COAT 的 4 个下游任务里只有 1 个高于基线；SDP4Bit 只用 validation loss 评估。
4. 现有 FP8 训练方案**专门为 AdamW 设计**，对 Muon 这类矩阵优化器没有对应结论。

**研究动机**：

作者的切入点是把问题从"量化格式问题"重新定义为"**坐标系问题**"。如果误差的根源是各向异性的局部几何与轴对齐的量化格点之间的错配，那么不改量化器、只换坐标系就应该有效，而且这个改动是**可加的**——它不与任何现有的量化格式、collective、优化器冲突。

### 1.2 问题定义 (Problem Definition)

**具体问题**：在数据并行的梯度同步路径上，把 FP32/BF16 的权重梯度降到 FP8 传输，如何在保住模型质量的前提下拿到带宽收益。

- **输入**：某线性层的权重梯度 $W_g \in \mathbb{R}^{d_\text{out} \times d_\text{in}}$（各 DP rank 的本地梯度）。
- **输出**：跨 DP 组同步平均后、回到欧氏坐标、交给优化器的梯度 $\widehat{W}_g$。
- **约束**（论文反复强调，是它的核心卖点）：不改优化器、不改模型、不改训练配方、不改 collective、不改低精度格式。**只改通信时使用的坐标系。**
- **评估指标**：一步 FP8 往返的重构保真度（RelL2 / Cos / MaxErr / MSE）、validation loss、14 个下游任务、端到端 step time、显存开销。

**问题形式化**：

DP 同步的目标是

$$\bar{g} = \frac{1}{R}\sum_{r=1}^{R} g^{(r)}$$

论文观察到，欧氏空间的量化误差是**方向相关**的。设某层局部几何由 Fisher 矩阵 $F(\theta)$ 描述，扰动的局部平方长度为 $\|\Delta\theta\|_F^2 = \Delta\theta^\top F(\theta)\Delta\theta$。当 $F$ 的条件数很大（各向异性）时，轴对齐的量化格点与这个椭球是错配的。GIFT 要找的是一个变换 $T$，使得梯度在 $T$ 之下的分布接近各向同性，从而让轴对齐的量化在各方向上引入可比的误差。

### 1.3 解决方案 (Solution)

**核心思路**：

用 K-FAC 的分块 Kronecker 近似拿到每层局部几何 $F_W \approx A \otimes G$（$A = \mathbb{E}[aa^\top]$ 是输入侧二阶统计，$G = \mathbb{E}[\delta\delta^\top]$ 是输出梯度侧二阶统计），对 $A$、$G$ 做 Cholesky 分解，用它们的**逆因子**把梯度白化到度量球是正球的坐标系里，在那里做 FP8 量化和 collective，同步完再用正因子映射回欧氏坐标交给优化器。**K-FAC 在这里只被用作一个可计算的局部度量来定义临时通信坐标，不是优化器，也不做自然梯度更新。**

**方法概述**：

1. **完整双侧变换（概念形式）**：$\widetilde{W}_g = L_G^{-1} W_g L_A^{-\top}$，通信后 $\widehat{W}_g = L_G \widehat{\widetilde{W}}_g L_A^\top$。数学依据是 $\|\Delta W\|_{F_W}^2 = \operatorname{tr}(A\Delta W^\top G \Delta W) = \|L_G^\top \Delta W L_A\|_F^2$，即 K-FAC 椭球被因子变换映射成欧氏 Frobenius 球。
2. **简化 I：只留输入侧。** 一步 FP8 往返分析显示输出侧几乎没贡献（RelL2 5.283e-2 vs 欧氏基线 5.282e-2），而只用输入侧已经几乎等于完整双侧（1.768e-2 vs 1.771e-2）。于是彻底删掉输出侧：$\widetilde{W}_g = W_g T_A$。
3. **简化 II：秩 32 低秩近似。** 对角近似（5.262e-2）几乎等于没做，说明"逐维缩放"不足以刻画有用的几何；分块近似（block-32 是 3.168e-2）明显不如低秩；低秩 8/16/32 分别是 1.958e-2 / 1.731e-2 / 1.721e-2。取 **rank-32** 作为工作点。
4. **简化 III：选择性部署。** 在 32-GPU 的 600M 预训练里 profile 前 100 步，对每个 MLP 层（fc1 与 fc2）统计 FP8 编码值撞到上下边界的比例作为"数值脆弱度"打分。分布高度集中：**排名前 13 全是 fc2 层**，之后打分明显掉下去。只对这 13 层开几何分支，其余走原欧氏快路径。
5. **运行时**：选中层集合 $\mathcal{S}$ 在训练前固定；输入侧几何因子**每 K=50 步刷新一次**；几何分支在变换后的坐标里做**局部 scale + 误差反馈**。

**技术细节**：

*输入侧白化变换（Eq. 18/19）*
- 作用：把输入侧 K-FAC 度量椭球映射成 Frobenius 球，使量化误差在各方向上更均匀。
- 实现：$\widetilde{W}_g = W_g L_A^{-\top}$，通信后 $\widehat{W}_g = \widehat{\widetilde{W}}_g L_A^\top$。是对梯度矩阵的**右乘**，即沿 $d_\text{in}$ 维混合、逐行独立（这一点对分片实现极其关键，见 §5.1）。
- 创新：K-FAC 一贯被用作预条件器（优化器侧），这里第一次被用作**通信侧的临时表示**。

*数值脆弱度 profiler*
- 作用：决定哪些层值得付几何变换的代价。
- 实现：对每个模块展平其直接参数梯度，算一个同步的 FP8 scale，编码成 FP8，统计撞上/下边界的频率，按 upper+lower 边界命中率之和排序，在 100 步窗口上取平均。
- 创新：这是全文**最可复用、成本最低**的组件——它跟 GIFT 的几何主张解耦，任何做低精度通信的人都能拿去回答"我的模型敏感度集中在哪几层"。

*变换坐标系下的误差反馈（Algorithm 1 第 16/20 行）*
- 作用：把量化残差累积在通信实际发生的坐标系里。
- 实现：$\widetilde{U} \leftarrow U + R$，量化/反量化后 $R \leftarrow \widetilde{U} - \widetilde{U}_\text{deq}$。
- **注意：这是论文"只改坐标系"这一核心主张的一个漏洞**——欧氏基线分支（第 8–13 行）**没有**误差反馈。见 §2.4。

**算法/架构描述**：

预训练时所有层共享同一个通信核心（量化 → collective → 反量化）。多数层直接以欧氏坐标进入这个核心；被选中的脆弱层先做输入侧低秩变换、进核心、出来后映射回去。离线阶段跑一次 profiling 定下 $\mathcal{S}$；在线阶段每 50 步刷新一次 $L_A$。

两个分支的具体差异（对照 Algorithm 1）：

| | 非选中层（欧氏） | 选中层（GIFT） |
|---|---|---|
| scale | `AllReduce_MAX` 全局同步 | **局部 scale**，只在特定步同步 |
| 误差反馈 | **无** | **有**（在变换坐标里） |
| 变换 | 无 | $W_g L_A^{-\top}$，通信后 $\cdot L_A^\top$ |
| collective | `AllReduce_SUM` on FP8 | `AllReduce_SUM` on FP8 |

## 二、实验效果 (Experimental Results)

### 2.1 实验设置 (Experimental Setup)

| 项 | 内容 |
|---|---|
| 数据集 | OpenWebText |
| 模型 | Llama 风格 **~300M（seq 4096）** 与 **~600M（seq 2048）**。两者序列长度不同，论文理由是"为了塞进显存" |
| 框架 | Megatron-LM |
| 优化器 | **Muon**，lr 5e-4，cosine decay，min lr 5e-5 |
| Batch | global 512，micro 4 |
| 基线 | **FP32**（高精度参考）、**layer-wise 欧氏 FP8**（主对照）、BF16、per-block-512 欧氏 FP8、full K-FAC |
| 指标 | FP8 往返 RelL2/Cos/MaxErr/MSE；validation loss；14 个下游任务；step time；显存 |
| 硬件 | **TACC Vista**，NVIDIA GH200 Grace Hopper Superchip，**每节点 1 张 GPU + 96 GB HBM3**。端到端预训练用 **32 GPU**；step-time 扩展曲线扫到 **64 GPU** |

> **口径提醒（重要）**：正文明确写"除非另有说明，所有端到端预训练实验用 32 GPU"，而摘要/结论的 **7.6% 是 64 GPU 上的 step-time 结果**。也就是说，**收敛/下游质量的证据来自 32 GPU 的跑，性能数字来自 64 GPU 的另一组跑**，两者不是同一批实验。

基线选择的理由（论文在 §VI-A 交代得比较诚实）：BF16 梯度通信在 14 个下游任务里 7 个匹配 FP32，但绝对值整体略低，所以用 FP32 当高精度参考；per-block（block size 512）欧氏 FP8 只有 4/14，弱于 layer-wise，所以主对照用更强的 layer-wise。

### 2.2 主要结果 (Main Results)

**FP8 一步往返重构误差（Table I，在欧氏梯度空间里对照原 FP32 梯度）**

| 方法 | RelL2 ↓ | Cos ↑ | MaxErr ↓ | MSE ↓ |
|---|---|---|---|---|
| 欧氏基线 | 5.281973e-02 | 9.986041e-01 | 1.625657e-04 | 1.289936e-10 |
| 仅输出侧 | 5.282879e-02 | 9.986036e-01 | 1.629426e-04 | 1.290378e-10 |
| **仅输入侧** | **1.768108e-02** | **9.998500e-01** | **5.332805e-05** | **1.445418e-11** |
| 完整 K-FAC（双侧） | 1.770532e-02 | 9.998502e-01 | 5.332805e-05 | 1.449384e-11 |

**结论极干净：输出侧完全没用，输入侧一个人干完了双侧的活。** 这是全文最扎实的一个实验。

**端到端时间（64×GH200，Llama-600M，相对 FP32）**

| 方法 | 梯度载荷缩减 | 端到端时间缩减 |
|---|---|---|
| 直接欧氏 FP8 | 75.0% | **10.79%** |
| **GIFT** | 75.0% | **7.6%** |

**GIFT 比直接欧氏 FP8 慢 3.19 个百分点**——这是几何变换的净开销。论文自己说得很明白："GIFT remains slower than direct Euclidean baseline because it introduces additional geometry-aware computation."

**显存开销（相对直接欧氏基线）**：300M **+3.33%**，600M **+8.98%**。来源是选中层的输入侧低秩因子与变换坐标下的误差反馈缓冲。

**Validation loss**：GIFT 与欧氏基线**轨迹几乎重合**，两者都"reasonably close to FP32"。论文自己承认 loss 上区分不出来，因此把下游任务当作决定性检验。

**下游任务（Table III，"Wins vs. FP32" = 在多少个任务上超过 FP32）**

| 模型 | 方法 | Wins vs. FP32 |
|---|---|---|
| 600M | BF16 | 7/14 |
| 600M | per-block 欧氏 FP8 | 4/14 |
| 600M | layer-wise 欧氏 FP8 | 5/14 |
| 600M | **GIFT** | **7/14** |
| 300M | layer-wise 欧氏 FP8 | 4/14 |
| 300M | full K-FAC | 6/14 |
| 300M | **GIFT** | **7/14** |

**关键发现**：

- 输入侧几何贡献了完整双侧变换 **99%+** 的保真收益；输出侧贡献约等于零。
- 低秩 32 把 RelL2 相对欧氏基线降 **67.4%**（5.281973e-02 → 1.720702e-02），而**对角近似基本无效**（5.262e-2）——说明有用的几何是**跨维度耦合**的，不是逐维缩放能捕捉的。这条对做量化的人有直接意义。
- 数值脆弱度**高度集中在 fc2**：前 13 名全是 fc2，第一个 fc1 紧随其后。
- 低精度通信的系统收益**随规模上升**：GPU 数越多、模型越大，FP8 相对 FP32 的优势越明显；GIFT 与欧氏 FP8 的差距在大规模下**被通信收益摊薄**。

### 2.3 消融实验 (Ablation Study)

**输入侧近似方式（Table II）**

| 配置 | RelL2 | 相对欧氏基线 |
|---|---|---|
| 欧氏基线 | 5.281973e-02 | — |
| 输入侧 full-A | 1.768108e-02 | −66.5% |
| 输入侧 **diag-A** | 5.262250e-02 | **−0.4%（基本无效）** |
| 输入侧 block-A-32 | 3.168243e-02 | −40.0% |
| 输入侧 block-A-64 | 2.754295e-02 | −47.9% |
| 输入侧 block-A-128 | 2.431718e-02 | −54.0% |
| 输入侧 low-rank-A-8 | 1.958074e-02 | −62.9% |
| 输入侧 low-rank-A-16 | 1.731027e-02 | −67.2% |
| **输入侧 low-rank-A-32** | **1.720702e-02** | **−67.4%** |

**消融结论**：

- **低秩 >> 分块 >> 对角。** rank-16 已经拿到 67.2%，rank-32 只多 0.2 个百分点；论文选 32 但明确声明"这是本设定下的工作点，不是模型无关的常数"。**从数据看 rank-16 是更好的成本/收益点，论文没解释为什么不选它。**
- block-A-128 用了 4 倍于 rank-32 的存储，效果还差一截（2.43e-2 vs 1.72e-2）。分块结构与梯度真实的耦合结构不匹配。
- 300M 上 full K-FAC（6/14）**不如**选择性 GIFT（7/14），论文据此论证"选择性部署比到处上重型几何更好"。这个论证站不住，见下。

### 2.4 对实验结论的独立复核（本笔记补充，非原文）

这一节是我自己算的，论文没有给。**结论是：GIFT 的性能数字成立，质量数字不成立。**

**(a) "Wins vs. FP32" 是个坏指标，而全文的质量主张只靠它。**

这个指标数的是"在多少个任务上超过 FP32"，而不是"比对照方法好多少"。在 300M–600M 规模上，Table III 里的多数任务本来就在随机水平附近（WiC 的 FP32 值恰好是 0.5000，RTE 在 0.51 附近，都是二分类的碰运气区间），所以"超过 FP32"更多是噪声的符号而不是质量的信号。看 GIFT 那 7 个 win 里的边际：

- **LAMB-STD：0.3722 vs FP32 的 0.3716**，赢了 **0.0006**。
- **WiC：0.5031 vs 0.5000**，赢了 0.0031，而 0.5000 是二分类的随机基线。
- PIQA：0.6763 vs 0.6719，赢 0.0044。

三个"胜场"合起来的总优势不到 0.01。把这三个换个种子就可能全翻。

**(b) 换成头对头比较，600M 上是欧氏基线赢。**

同一张 Table III，逐任务比 Euclidean 与 GIFT（不看 FP32）：

| 欧氏更好 | GIFT 更好 |
|---|---|
| BOOLQ、CB-ACC、RCD-F1、WSC、RACE、M-QA、WINO.、LAMB-STD | COPA、MUL-RC、RTE、WiC、LAMB.、PIQA |
| **8 项** | **6 项** |

14 项均值（口径同样粗糙，但和"数胜场"一样粗糙，而结论相反）：

| 600M | 14 任务均值 |
|---|---|
| 欧氏 FP8 | **0.5186** |
| FP32 | 0.5060 |
| **GIFT** | **0.5032** |
| per-block FP8 | 0.5023 |
| BF16 | 0.5017 |

**GIFT 的均值是所有 FP8 方法里最低的**，而欧氏基线最高。两个指标给出完全相反的排序，说明这张表噪声主导、无法支撑"GIFT 保持得更好"的结论。

驱动这个差异的两项是 CB-ACC（欧氏 0.4107 vs GIFT 0.3036）与 WSC（0.5865 vs 0.4712）——**恰好是 SuperGLUE 里验证集最小的两个任务**（CB 约 56 条、WSC 约 104 条，外部知识，非原文），几条样本的翻转就能移动 10 个百分点。

300M 上同样的复核：均值 FP32 0.4914 > **full K-FAC 0.4895** > GIFT 0.4788 > 欧氏 0.4747。也就是说，**论文用来论证"选择性优于完整 K-FAC"的那个 7/14 vs 6/14，在均值口径下是反过来的**。§2.3 那条消融结论因此不成立。

**(c) 基线是 FP32，不是 BF16 —— 这把头条数字放大了约一倍。**

生产训练没有人用 FP32 做梯度通信，标准是 BF16。用论文自己的数字反推（假设通信时间与载荷线性）：

- 欧氏 FP8 省 10.79% 端到端、载荷降 75% ⟹ **FP32 下 DP 梯度通信约占 step time 的 14.4%**。
- BF16 载荷降 50% ⟹ 端到端省约 **7.19%**。
- 于是相对 **BF16 基线**：
  - 欧氏 FP8：$(10.79 - 7.19)/(100-7.19) \approx$ **+3.9%**
  - **GIFT：$(7.60 - 7.19)/92.81 \approx$ +0.4%**

**GIFT 相对 BF16 基本是打平。** 而且这两个数还是**上界**——BF16 不需要 scale 的 AllReduce_MAX、不需要量化/反量化、不需要误差反馈缓冲，这些固定开销只有 FP8 路径要付；同时小消息下通信时间不是严格线性于字节数，也会进一步压缩 FP8 的收益。

**(d) "只改坐标系"这个核心主张与 Algorithm 1 不符。**

对照两个分支：GIFT 分支有**误差反馈**（第 16/20 行）和**局部 scale**（第 17 行，只在特定步同步），欧氏分支两样都没有（第 9–10 行是全局同步 MAX scale，无 EF）。所以 GIFT vs 欧氏的对比同时改了三件事：坐标系、误差反馈、scale 粒度。**缺失的关键消融是"欧氏 + 误差反馈"** —— 有相当的可能性，观察到的（本就微弱的）质量差异主要来自误差反馈而不是几何。任何要移植这个方法的人必须先补这个对照。

**(e) 若干未定义的量，直接影响可复现性与数值稳定性。**

- **$A$ 怎么在 DP 组之间取得一致？** 论文全文没说。这不是细节：变换要在 collective 两侧抵消，所有 rank 必须用**同一个** $L_A$。如果每个 rank 用自己数据分片估出的本地 $A$，那么 $\sum_r W_g^{(r)} T_A^{(r)} \neq \left(\sum_r W_g^{(r)}\right) T_A$，映射回去就是错的。这是个**潜在正确性缺陷**，不只是遗漏。
- **阻尼系数未给。** Eq. (9) 写的是"regularized K-FAC factors"的 Cholesky，但正则化强度全文没有出现。而各向异性正是本文的前提，$A$ 天然病态；rank-32 近似更让它奇异，$L_A^{-\top}$ 必须阻尼。**这是移植时第一个要扫的超参**，也是最可能的发散来源。
- **局部 scale 下的 `AllReduce_SUM` 语义可疑。** 第 17–26 行：各 rank 用**自己的** $s_\text{loc}$ 量化，然后对 FP8 码求和，再用**自己的** $s_\text{comm}$ 反量化。各 rank scale 不同时，直接加码值再乘单一 scale 在数学上是不一致的。论文没有讨论。
- 训练步数/token 量、warmup、weight decay、Muon 的 NS 迭代次数与 momentum、"scale-synchronization step"的频率、300M/600M 的具体架构（层数/宽度/头数）**全部未给**。
- **单种子。** 论文自陈"would be strengthened by additional seeds"。

**(f) 规模证据严重不足 —— 这是最该记住的一条。**

**300M 和 600M 对一个"收敛性"主张来说是弱到不能用的规模。** 具体缺什么：

- **缺规模扫描。** 只有两个点，且两个点用了**不同的序列长度**（4096 / 2048），所以连"300M → 600M 的趋势"都不是一个受控对照。
- **梯度各向异性的结构随规模变化是已知现象**，而全文的机理主张恰恰建立在各向异性的具体形态上。"前 13 层全是 fc2"这种集中性在 8B/70B 上是否还成立，完全没有证据；论文自己也只敢说 13 这个数"不是模型无关的常数"。
- **训练时长短。** 未报步数，但 32 GPU / global batch 512 的设置下不可能接近生产 horizon。而低精度通信的失效模式典型是**慢性漂移**——短跑看不出来。GIFT 每 50 步换一次坐标系（见 §5.4），这类周期性扰动的累积效应恰恰需要长 horizon 才暴露。
- **dense-only，没有 MoE。** 全文是 transformer 线性层的 fc1/fc2，没有 expert GEMM、没有 EP 维度的梯度归约。
- **纯 DP，没有 TP/PP。** §II-A 花了整节介绍 3D 并行，但实验一个 TP 都没开。而 GIFT 选中的层全是 **fc2**，其 $d_\text{in}$ 恰好是 Megatron row-parallel 线性层被 TP 切开的那一维（见 §5.1）——论文因此从未碰到自己方法最尖锐的工程约束。
- **对照组的规模落差。** 论文批评 SDP4Bit"只用 validation loss 评估"，而 SDP4Bit 做到 GPT-6.7B（质量）/ 18B（速度）、有收敛性理论、且**开源**。用 600M 去批评 6.7B 的评估口径，姿态是站不住的。

**净判断**：Table I / Table II 的保真度分析是可信且有用的（受控、机理清楚、结论干净）。**7.6% 的性能数字在它自己的口径下也是可信的。** 不可信的是"GIFT 质量更好"这个结论——它建立在一个坏指标、一个被误差反馈污染的对照、和一个噪声主导的下游表上。真正被这篇论文确立的事实只有一条：**在 FP8 往返的重构误差意义上，输入侧低秩白化能把误差降 67%，而这个收益不需要完整 K-FAC、不需要输出侧、也不需要 rank 超过 16–32。**

### 3.2 技术路线对比 (Technical Approach Comparison)

**路线 A：改传什么（压缩率路线）**
- 代表工作：DGC（稀疏化）、PowerSGD（低秩）、1-bit Adam、SDP4Bit（权重差分）。
- 核心思路：不传完整梯度，传一个更小的代理量。
- 优劣：压缩率可以做到很高（10×–600×），但改变了同步的数学对象，需要误差补偿/动量修正来兜底，收敛性要单独论证；且稀疏/低秩的通信模式对 collective 库不友好。

**路线 B：改怎么表示（格式/缩放路线）**
- 代表工作：FP8-LM、COAT、Micikevicius 的 FP8 格式规范、直接 FP8 collective。
- 核心思路：保持传完整梯度，只降低每个数的位宽；设计重点在 scale 的统计量与粒度（per-tensor / per-layer / per-block / per-token）。
- 优劣：与 collective 库天然兼容（NCCL 2.24 / RCCL 都原生支持 FP8），工程侵入性最小；但压缩率被格式锁死（FP32→FP8 是 4×，BF16→FP8 是 2×），且质量损失只能靠调 scale 缓解，没有额外自由度。

**路线 C：改在哪个空间量化（坐标系路线）—— 本文**
- 代表工作：GIFT；机制上的近亲是 SDP4Bit 与 MXFP4 论文里的 **Hadamard 平滑**（数据无关的旋转），以及推理量化里的 QuaRot/SpinQuant 一系。
- 核心思路：量化器和格式都不动，先做一个**可逆变换**让分布变得对量化友好，量化通信之后再变回来。
- 优劣：与 A、B 完全正交，可以叠加；不改变同步的数学对象（在所有 rank 共用同一变换的前提下）；代价是变换本身的算力与显存，以及维护变换所需的统计量。

### 3.3 本文定位 (This Paper's Position)

- **相对路线 A 的改进**：GIFT 不改变被同步的量，因此不需要单独的收敛性论证（在理想抵消的前提下），也不需要稀疏/低秩带来的非常规通信模式。这是它相对 PowerSGD/DGC 最实在的工程优势。
- **相对路线 B 的改进**：论文的诊断是有价值的——它指出**在欧氏空间里调 scale 这条路已经到头了**（Table II 里的 diag-A 就是"最精细的逐维 scale"，几乎无效），要再进一步必须换空间。这个诊断本身比 GIFT 这个具体系统更有价值。
- **相对路线 C 内部同类的差异**：SDP4Bit 用的是 **Hadamard**（数据无关、固定、正交），GIFT 用的是 **K-FAC 白化**（数据相关、每 50 步刷新、非正交）。GIFT 的变换携带了更多信息（Table II 的 67.4% 就是证据），但也引入了 Hadamard 没有的三个负担：要维护二阶统计、要跨 rank 一致、要处理病态求逆。**这个取舍论文没有正面讨论，而它恰恰是移植时的核心决策点**（见 §5.4）。
- **独特贡献**：(1) 把低精度通信误差重新诊断为**坐标系与几何的错配**而非格式问题；(2) 一个干净的三段简化路径（去输出侧 → 低秩 → 选择性），每一步都有受控的保真度证据；(3) **数值脆弱度 profiler**，一个与主张解耦、可独立复用的工具。

### 摘要 (Abstract)

梯度通信是大语言模型（large language model, LLM）预训练的主要扩展瓶颈。以低精度格式（如 FP8 与 NVFP4）通信梯度可以显著降低通信量。已有方法通过欧氏空间（Euclidean space）中的线性或非线性映射来量化梯度，这往往会损害模型性能，因为高度各向异性（anisotropic）的梯度会引入方向相关的失真。我们提出 GIFT，一种几何感知的梯度缩放方法，它在几何感知坐标（geometry-aware coordinates）中执行低精度通信。通过在量化前把梯度变换到近各向同性（near-isotropic）的空间，GIFT 使低精度表示对其高精度对应物的保真度大幅提升。GIFT 只改变低精度梯度通信所使用的坐标系，不改变优化器、训练配方、通信集合操作（communication collective）或低精度格式。我们还设计了一个简化的几何感知变换算法，采用低秩近似（low-rank approximation）与选择性应用（selective application）来平衡计算开销与通信削减。我们用 Llama-300M 与 Llama-600M 模型检验 GIFT 的经验收敛性。结果表明，在 64 张 NVIDIA GH200 Superchip 上，GIFT 使 Llama-600M 的端到端预训练时间减少 7.6%，同时在相同优化器与相同通信路径下，比直接的欧氏 FP8 通信具有更好的下游任务保持特性（downstream task preservation profile）。

### I. 引言 (Introduction)

梯度通信是分布式 LLM 预训练的主要扩展瓶颈 [1]。在数据并行、3D 并行或更复杂的并行预训练策略中，优化器需要跨图形处理器（GPU）通信梯度。标准通信库（如 NCCL 与 MPI）实现的是环形 all-reduce 算法 [2]，其代价取决于模型规模与作业规模（即 GPU 数量）。已有工作报告，在 128 张 NVIDIA A100 上预训练 GPT-8.3B 时，通信占整体预训练时间的 40% [3]。

通过低精度梯度来降低通信量是削减通信开销的有效途径，因为每个梯度表示所节省的比特会直接按比例转化为带宽消耗的下降。已有的低精度训练技术，如 FP8-LM [4] 与 COAT [5]，主要在欧氏张量坐标中做缩放与量化，这仍可能导致模型性能退化。它们都是专为 AdamW 优化器 [6] 设计的。FP8-LM 对模型权重、激活、梯度与一阶矩使用 FP8 格式，而二阶矩以 16 位格式存储以保证除法的稳定性。COAT 使用动态范围策略（即 $S_X = \frac{\text{amax}(X_\text{FP32})}{\Delta^\text{E4M3}_\text{MAX}}$）与混合粒度的激活量化来量化二阶矩与激活，而梯度仍保持 16 位以维持训练稳定性。SDP4Bit [7] 利用分片数据并行的模型放置，通过傅里叶变换与分层 all-to-all 通信实现 4 位梯度通信。然而，FP8-LM 与 COAT 都没有达到与 BF16 基线相当的模型性能。FP8-LM 显示，十个下游任务中有七个的表现差于基线。COAT 的四个下游任务中只有一个得分高于基线。SDP4Bit 只用验证损失来评估模型性能。

多数已有工作提出的是整体量化（holistic quantization）方案，不仅量化梯度，还量化模型参数与优化器状态。这使得隔离"低精度格式下的梯度"所带来的影响、以及论证额外计算开销与通信削减之间的权衡变得困难。在本工作中，我们**只**关注使用 FP8 格式的梯度通信（NCCL 2.24 于 2025 年初加入了原生 FP8 支持）。我们系统性地分析了在 Llama 模型训练中，Muon 优化器 [8] 使用 FP8 梯度时的优化过程。GIFT 只改变低精度梯度通信所使用的坐标系；它不改变优化器、模型、训练配方、通信集合操作或 FP8 格式。我们观察到梯度往往是高度各向异性的，因此在欧氏空间中直接量化会使某些方向的失真大于其他方向，导致同步后的更新偏离其高精度对应物。如图 1 所示，在欧氏空间中对两个轴施加统一的缩放因子会造成不同程度的误差。而通过 Fisher 白化（Fisher whitening）把梯度变换到黎曼流形（Riemannian manifold）上，得到的分布则接近各向同性。

**图 1**：真实梯度样本在不同坐标系下的二维投影。在原始的欧氏参数空间中（左），梯度高度拉长且各向异性。经过几何感知变换后（右），同一批梯度变得更圆、相关性更弱，使得低精度量化对方向的敏感性下降。

受此观察启发，我们提出 GIFT，一种实用的几何感知梯度缩放技术，用以改善 FP8 梯度通信的保真度—效率权衡。核心思想很简单：在几何感知坐标而非原始欧氏坐标中量化梯度，使得缩放到 FP8 时各维度引入的误差相当。GIFT 由基于 K-FAC [9, 10, 11] 的实用局部几何近似支撑（见 §II-B），后文中我们把完整的几何近似称为 K-FAC。我们**仅**用这一近似来构造临时的通信坐标，而不是用 K-FAC 或自然梯度步骤来替换优化器更新。把 K-FAC 朴素地应用到所有梯度上，其模型性能优于已有的 FP8 缩放技术。然而 K-FAC 的计算复杂度使其不够实用，因为额外的计算时间会超过所节省的通信时间。因此我们挑选出对量化最敏感的层，只对这些层施加简化的 K-FAC，其余层使用标准的欧氏缩放。这一选择性策略降低了 K-FAC 的计算开销，同时保住了由此获得的模型性能。

我们在 Megatron-LM [12] 框架中实现了 GIFT，并用 OpenWebText [13] 数据集预训练 Llama-300M 与 Llama-600M。我们比较了使用 GIFT、FP32 和欧氏基线（即 layer-wise 缩放）预训练得到的模型性能。我们的误差分析表明，相对欧氏基线，GIFT 把误差（即 FP8 与 FP32 下平均梯度之差）最多降低 **67.4%**。预训练研究表明，在相同优化器与相同通信路径下，用 GIFT 预训练的 Llama 模型比欧氏缩放方案具有更好的下游任务保持特性。相对 FP32 梯度，GIFT 把梯度通信量降低 **75.0%**，在 64 张 GH200 superchip 上使整体预训练时间减少 **7.6%**。这里的 75.0% 指的是梯度载荷（payload）大小，而端到端加速较小，因为总预训练时间还包括前向与反向计算、优化器更新、量化与反量化、几何变换、同步开销以及非梯度通信。在同一规模下，直接的欧氏 FP8 达到 **10.79%** 的削减，说明 GIFT 是用一部分原始 FP8 加速换取了更好的下游保持特性。

本文有三项主要贡献：

- **对低精度缩放误差的新诊断。** 我们指出，欧氏梯度缩放的误差是**各向异性的局部梯度几何与轴对齐量化之间的错配**。
- **一个选择性的几何感知缩放设计。** 我们提出 GIFT，它对大多数层保持标准的欧氏缩放，只在模型性能的收益足以抵消代价的地方施加几何感知缩放。
- **显著更好的保真度—效率权衡。** 我们表明 GIFT 相对直接欧氏 FP8 改善了下游保持特性，同时保留了相对 FP32 的一部分 FP8 加速，使几何感知的低精度通信在我们的 Megatron-LM 预训练实验中变得实用。

7.6% 的整体时间削减可能被视为微小。然而，现代 LLM 是在数万张 GPU 上预训练数月的。即便 7.6% 的时间削减也可能折合数百万美元。另一方面，GPU 集群中的互联是共享资源，带宽消耗的下降能带来更高效的网络共享。随着互联带宽的增长慢于计算单元（即 GPU），通信瓶颈正变得日益突出。尽管我们的实验基于 FP8，但几何变换的开销**大体上与低精度通信格式无关**，因此在软硬件支持成熟后，同样的原理可以应用于未来的 FP4 通信。这一趋势使几何感知通信成为未来更低比特 LLM 预训练系统的一个有前景的方向。

### II. 背景 (Background)

本节介绍本文考虑的通信设定，以及后文用来定义 GIFT 通信坐标的、基于 K-FAC 的局部度量。我们先概述数据并行与 3D 并行 LLM 预训练中通信是如何产生的，然后引入用于获得可计算局部几何的、逐层分块对角 K-FAC 近似 [14, 12, 15, 16, 17, 18, 10, 9, 11, 19]。

#### II-A 数据并行与 3D 并行预训练中的通信

只要模型状态、激活或梯度被划分到多个设备上，分布式 LLM 预训练就需要通信。具体的通信模式取决于并行化策略，但在所有情况下，通信都位于每次预训练迭代的关键路径上，并可能随着模型规模与系统规模的增长成为主要的扩展瓶颈 [1, 14, 12, 3]。

**数据并行。** 在数据并行（DP）预训练中，每个 worker 存储完整的模型副本，处理 mini-batch 的不同分片。反向传播之后，不同 worker 上计算出的本地梯度必须在优化器更新之前聚合，以保证所有副本同步 [14, 12, 17]。若 worker $r$ 产生本地梯度 $g^{(r)}$，则同步后的梯度为

$$\bar{g}=\frac{1}{R}\sum_{r=1}^{R}g^{(r)} \tag{1}$$

其中 $R$ 是 DP worker 数。实践中这一聚合通常由 all-reduce 实现，或在 ZeRO 式预训练这类分片设定下等价地由 reduce-scatter 后接 all-gather 实现 [2, 17, 18]。由于每次迭代都要通信完整的梯度集合，通信代价随模型规模与 worker 数一起增长，使 DP 梯度通信成为压缩的首要目标 [20, 21, 22, 23, 18]。

**3D 并行。** 现代大规模 LLM 预训练常把数据并行（DP）、张量并行（TP）与流水并行（PP）结合起来，通常称为 3D 并行 [12, 14, 3]。在这种设定下，通信沿三条不同的路径产生。

第一，在张量并行中，单个层被划分到多个设备上，因此前向与反向过程中层内的部分张量结果必须交换。取决于算子与划分规则，这类通信通过 all-reduce、all-gather 或 reduce-scatter 等集合操作实现，用以在 TP rank 之间组装输出或累加部分梯度 [14, 12]。第二，在流水并行中，模型被按阶段划分，相邻阶段在前向传播中通过点对点收发通信边界激活、在反向传播中通信边界梯度 [15, 16, 12]。第三，跨 DP 组，被复制的参数或优化器分片仍需要通信，以使分布式优化器施加一致的更新 [12, 17, 18]。

因此，3D 并行预训练包含多条语义不同的通信路径：TP 通信层内的部分张量结果，PP 通信阶段间的激活与梯度，DP 跨副本通信梯度或优化器更新信息 [12, 15, 16, 3]。**本文聚焦 DP 梯度通信路径。** 这一选择隔离出了与低精度压缩最直接兼容的通信瓶颈，并让我们能在通信步骤之外保持优化器语义不变的前提下研究梯度坐标选择的效果 [20, 22, 24, 7]。

#### II-B K-FAC 分块对角近似

Fisher 信息矩阵为神经网络优化中的参数扰动测量提供了一个局部度量 [10, 9]。设 $\theta$ 为模型参数，$F(\theta)$ 为 Fisher 矩阵。扰动 $\Delta\theta$ 的局部平方长度为

$$\|\Delta\theta\|_{F}^{2}=\Delta\theta^{\top}F(\theta)\,\Delta\theta \tag{2}$$

然而，对现代 LLM 而言，直接构造或求逆完整的 Fisher 矩阵是不可行的，因为它耦合了所有层的所有参数。

K-FAC 通过对 Fisher 的结构化近似使这一局部几何变得可计算。在标准 K-FAC 公式中，Fisher 被按层分块处理，每个块由两个更小因子的 Kronecker 积近似 [11, 19]。对于具有权重矩阵 $\{W_l\}_{l=1}^{L}$ 的模型，这一逐层近似可写为

$$F(\theta)\approx\operatorname{blockdiag}\left(F_{W_{1}},F_{W_{2}},\ldots,F_{W_{L}}\right) \tag{3}$$

其中每个对角块描述一层的局部几何。这一分块对角近似移除了跨层的曲率项，使该度量可以按层估计与应用。

对于权重矩阵 $W\in\mathbb{R}^{d_\text{out}\times d_\text{in}}$ 的线性层，设 $a$ 为该层的输入激活，$\delta$ 为对该层预激活输出的梯度。使用标准的列主序向量化约定，K-FAC 把逐层 Fisher 块近似为

$$F_{W}\approx A\otimes G,\qquad A=\mathbb{E}[aa^{\top}],\qquad G=\mathbb{E}[\delta\delta^{\top}] \tag{4}$$

其中 $A\in\mathbb{R}^{d_\text{in}\times d_\text{in}}$ 刻画输入侧的二阶统计，$G\in\mathbb{R}^{d_\text{out}\times d_\text{out}}$ 刻画输出梯度侧的二阶统计 [11, 19]。因此，K-FAC 不必维护覆盖全部模型参数的完整 Fisher 矩阵，只需为每层维护小的结构化因子。

**本文不把 K-FAC 用作优化器，也不施加自然梯度更新。** 我们只把 K-FAC 块当作一个可计算的局部度量，用于定义通信坐标。优化器、模型架构与分布式训练结构保持不变；被修改的只有低精度梯度通信期间所使用的坐标系。

### III. 相关工作 (Related Work)

本节从三类总结相关工作：通信压缩、低精度 LLM 预训练、几何感知优化。

#### III-A 梯度通信压缩

有一长串工作通过降低通信量来削减分布式训练开销，代表方法包括量化、稀疏化、低秩近似以及与优化器绑定的通信方案 [20, 21, 22, 23, 18, 25, 3, 7]。这些方法表明，梯度通信常常可以在不完全牺牲优化质量的前提下被大幅削减，使通信压缩成为大规模预训练中一个实用的系统方向。近期工作进一步把这一趋势推向现代 LLM 场景下的更低比特通信，包括分片式与分层式的通信设计 [18, 25, 7]。我们的工作与已有方法方向一致，但机制不同：我们不修改通信模式、不降秩、也不引入稀疏性，而是研究**梯度通信所使用的坐标系如何影响低精度通信的保真度**。这些方法是重要的相关系统，但不是本研究的直接受控基线。QSGD 改变的是量化规则，DGC 引入稀疏性，PowerSGD 通信的是低秩梯度表示，1-bit Adam 与 Adam 式优化器动态耦合。LoCo 与本文关系密切，因为它同样针对低比特梯度通信，但其主要机制是**在原始梯度坐标中做误差补偿**。相比之下，GIFT 保持优化器、通信集合操作、FP8 格式与训练配方不变，只改变通信坐标系。

#### III-B 低精度 LLM 预训练

另一条密切相关的工作研究 FP8 及其他低精度格式在高效预训练中的应用 [26, 24, 27, 4, 5]。这些方法通常依赖在量化前对张量做缩放，使其数值更好地匹配目标格式的可表示范围 [24, 4]。在这一设定下，主要的设计问题在于如何选择缩放统计量，以及如何在降低精度的情况下维持稳定的预训练 [24, 4, 5]。FP8-LM 与 COAT 这类代表性系统表明，在精心设计的缩放规则下，低精度预训练可以扩展到预训练栈更广的部分，包括梯度、激活与优化器状态 [4, 5]。SDP4Bit 进一步研究了分片数据并行 LLM 预训练中的低比特通信，表明通信感知的平滑与分层量化可以显著缩小相对高精度基线的质量差距 [7]。它的设定改变了分片通信路径并联合设计了通信算法，而我们的实验是在同一条 all-reduce 路径下隔离坐标选择的影响。与这些整体式系统不同，GIFT 只关注梯度通信，不量化模型参数、激活或优化器状态。这些工作确立了缩放对低精度预训练与通信的实际重要性，但它们仍然在张量的原始欧氏坐标上操作。

#### III-C 几何感知优化与 GIFT 的定位

我们的工作也与几何感知优化相关，特别是自然梯度与 K-FAC 式近似 [10, 11, 19]。这些方法利用局部二阶结构对梯度做预条件，主要目的是提高优化效率或适应曲率。这与**把同一结构用作通信的临时表示**是不同的。相比之下，我们把同样的几何直觉用于另一个目的：提升低精度通信的保真度。GIFT 不把优化器变成二阶方法；它利用局部几何把梯度变换到更适合 FP8 量化的通信坐标中。变换后的梯度在优化器更新之前被映射回去，因此优化器接收到的是原始参数坐标下的梯度。在这个意义上，GIFT 与既有的通信压缩方法和几何感知优化方法都是互补的。GIFT 与已有低精度技术的区别在于：它探索的是**在另一个坐标系中施加量化**，而不是在欧氏空间里选一个更好的 scale。

### IV. 设计 (Design)

本节介绍几何感知低精度梯度通信的设计。核心思想是保持标准的分布式预训练与优化器流水线不变，但改变梯度量化与通信所处的坐标系。GIFT 不在欧氏坐标中直接通信权重梯度，而是把它们映射到 K-FAC 局部度量所诱导的坐标中，在那个空间执行低精度通信，然后在优化器更新之前映射回来。

#### IV-A 几何感知通信坐标

我们关注线性层的权重梯度

$$W_{g}\in\mathbb{R}^{d_\text{out}\times d_\text{in}} \tag{5}$$

在传统的低精度通信中，$W_g$ 直接在欧氏参数坐标中被缩放、量化、通信、反量化并求平均。这样做效率高，但它对所有方向一视同仁。当局部梯度几何是各向异性的（如图 1 所示），同一个低精度 scale 必须覆盖幅值差异极大的方向。结果是量化误差可能变得强烈依赖方向：大方差方向主导了 scale，而小方差方向承受相对更大的失真。

**K-FAC 给出的局部度量。** 沿用 §II-B 引入的 K-FAC 块，线性层的局部度量被近似为

$$F_{W}\approx A\otimes G,\qquad A=\mathbb{E}[aa^{\top}],\qquad G=\mathbb{E}[\delta\delta^{\top}] \tag{6}$$

其中 $A$ 刻画输入侧二阶统计，$G$ 刻画输出梯度侧二阶统计。对层权重的小扰动 $\Delta W$，对应的 K-FAC 局部平方长度为

$$\|\Delta W\|_{F_{W}}^{2}=\operatorname{vec}(\Delta W)^{\top}(A\otimes G)\operatorname{vec}(\Delta W) \tag{7}$$

利用标准的 Kronecker 与迹恒等式，这可以等价写为

$$\|\Delta W\|_{F_{W}}^{2}=\operatorname{tr}\left(A\Delta W^{\top}G\Delta W\right) \tag{8}$$

设

$$A=L_{A}L_{A}^{\top},\qquad G=L_{G}L_{G}^{\top} \tag{9}$$

为**正则化后**的 K-FAC 因子的 Cholesky 分解。把这些分解代入式 (8) 得

$$\|\Delta W\|_{F_{W}}^{2}=\operatorname{tr}\left(L_{A}L_{A}^{\top}\Delta W^{\top}L_{G}L_{G}^{\top}\Delta W\right)=\operatorname{tr}\left(L_{A}^{\top}\Delta W^{\top}L_{G}L_{G}^{\top}\Delta WL_{A}\right)=\left\|L_{G}^{\top}\Delta WL_{A}\right\|_{F}^{2} \tag{10}$$

因此，K-FAC 椭球

$$\left\{\Delta W:\|\Delta W\|_{F_{W}}^{2}\leq\epsilon\right\} \tag{11}$$

被因子变换

$$U=L_{G}^{\top}\Delta WL_{A} \tag{12}$$

映射为欧氏 Frobenius 球

$$\left\{U:\|U\|_{F}^{2}\leq\epsilon\right\} \tag{13}$$

这说明 K-FAC 因子把局部的各向异性度量变成了一个度量球为正球的坐标系。等价地说，被局部 Fisher 几何拉伸或压缩的方向，在坐标变换之后被更均匀地缩放。

**对被通信的梯度做白化。** 上面的度量球论证解释了 K-FAC 因子的几何角色。对通信而言，我们在量化前对梯度施加相应的**逆因子**。具体地，完整的几何感知通信坐标定义为

$$\widetilde{W}_{g}=L_{G}^{-1}W_{g}L_{A}^{-\top} \tag{14}$$

这一变换也可以看作对逐层梯度统计的白化操作。在 Fisher/K-FAC 近似下，与 $\operatorname{vec}(W_g)$ 相关的主导二阶结构由同一组 Kronecker 结构因子表示。因此

$$\operatorname{vec}(\widetilde{W}_{g})=\left(L_{A}^{-1}\otimes L_{G}^{-1}\right)\operatorname{vec}(W_{g}) \tag{15}$$

移除了由 $A$ 与 $G$ 刻画的主导输入侧与输出侧缩放。在变换后的坐标中，梯度分布因而更接近各向同性，于是轴对齐的低精度量化格点与梯度的相互作用比在原始欧氏坐标中更均匀。

变换之后，GIFT 施加与欧氏基线**完全相同**的低精度通信流程：

$$\widehat{\widetilde{W}}_{g}=\operatorname{Comm}_\text{FP8}\left(\widetilde{W}_{g}\right) \tag{16}$$

其中 $\operatorname{Comm}_\text{FP8}(\cdot)$ 表示缩放、FP8 量化、集合通信、反量化与求平均。同步后的变换梯度随后被映射回欧氏坐标：

$$\widehat{W}_{g}=L_{G}\widehat{\widetilde{W}}_{g}L_{A}^{\top} \tag{17}$$

映射回来的梯度 $\widehat{W}_g$ 被交给与高精度基线、欧氏低精度基线完全相同的优化器。

重要的是，这一流程**只改变通信坐标**。它不改变模型架构、分布式并行化策略或优化器更新规则。因此 GIFT 不是 K-FAC 优化器，也不是自然梯度方法；它只是用 K-FAC 式的局部几何来提升低精度梯度通信的保真度。

**输入侧的实用形式。** 式 (14) 的完整双侧变换把几何原理讲清楚了，但在大规模 LLM 预训练中把它应用到每一层会带来可观的矩阵计算与显存开销。实践中，GIFT 使用同一思想的输入侧版本：

$$\widetilde{W}_{g}=W_{g}L_{A}^{-\top} \tag{18}$$

随后在变换坐标中做 FP8 通信，再逆映射

$$\widehat{W}_{g}=\widehat{\widetilde{W}}_{g}L_{A}^{\top} \tag{19}$$

这一输入侧形式保留了局部几何中最有用的部分，同时避免了维护并施加两个 K-FAC 因子的代价。它也可以被理解为把 K-FAC 度量的输入侧分量变成一个更各向同性的坐标系。具体地，若只使用输入侧度量，则

$$\operatorname{tr}\left(A\Delta W^{\top}\Delta W\right)=\left\|\Delta WL_{A}\right\|_{F}^{2} \tag{20}$$

因此输入侧的椭球几何同样被映射为欧氏 Frobenius 球。

式 (14) 的完整双侧公式揭示了几何原理，而式 (18) 的输入侧形式给出了 GIFT 实际使用的通信坐标。余下的系统问题是：实践中需要多少几何、输入侧因子必须被多精确地表示、以及几何感知路径应该被应用在哪里。§V 通过三项简化在经验上回答这些问题，并把坐标变换落地为最终系统：只保留输入侧几何、用低秩因子近似它、以及只对数值上最脆弱的层选择性应用。

最终系统通过三项设计决策回答这些问题：(i) 只保留输入侧几何；(ii) 用秩 32 的低秩表示近似它；(iii) 只在数值上最脆弱的层部署它。这些决策是**顺序做出**的：只有在重构研究表明相应的保真度损失很小之后，每一步才从完整公式中移除一项开销来源。

#### V-A 实用简化 I：只保留输入侧几何

§IV 的完整双侧公式是一个有用的概念起点，但对每个符合条件的层都施加变换的两侧，对大规模端到端预训练来说过于昂贵。因此我们先问：变换的哪一侧真正带来了实际的保真度收益？

为回答这个问题，我们在欧氏梯度空间中做一次受控的一步 FP8 往返分析。对每种方法，我们从一个 FP32 梯度出发，把它映射到对应的通信坐标，在那里做一次 FP32 → FP8 → FP32 的往返，再把结果映射回欧氏梯度空间，与原始 FP32 梯度比较。

我们报告四项重构指标：

$$\mathrm{RelL2}=\frac{\|\hat{g}-g\|_{2}}{\|g\|_{2}},\quad \mathrm{Cos}=\frac{\langle\hat{g},g\rangle}{\|\hat{g}\|_{2}\|g\|_{2}},\quad \mathrm{MaxErr}=\|\hat{g}-g\|_{\infty},\quad \mathrm{MSE}=\frac{\|\hat{g}-g\|_{2}^{2}}{n} \tag{21}$$

其中 $g$ 是原始 FP32 梯度，$\hat{g}$ 是 FP8 往返后重构的梯度，$n$ 是梯度张量的元素数。Cos 度量 FP8 往返是否保持了更新方向，而 RelL2、MaxErr 与 MSE 度量通信扰动的幅度与最坏情况规模。因此这些指标提供了一个在跑完整端到端预训练之前的、机制层面的保真度检验。表 I 报告结果。

**表 I**：完整变换与单侧变换的一步 FP8 往返重构误差，在欧氏梯度空间中对照原始 FP32 梯度测量。RelL2、MaxErr、MSE 越低越好；Cos 越高越好。

| 方法 | RelL2 | Cos | MaxErr | MSE |
|---|---|---|---|---|
| 欧氏基线 | 5.281973e-02 | 9.986041e-01 | 1.625657e-04 | 1.289936e-10 |
| 仅输出侧 | 5.282879e-02 | 9.986036e-01 | 1.629426e-04 | 1.290378e-10 |
| 仅输入侧 | 1.768108e-02 | 9.998500e-01 | 5.332805e-05 | 1.445418e-11 |
| K-FAC | 1.770532e-02 | 9.998502e-01 | 5.332805e-05 | 1.449384e-11 |

结果很清楚：输出侧变换相对欧氏基线只有微不足道的贡献，而输入侧变换在所有指标上已经几乎精确地匹配了完整的双侧变换。这说明，在我们 profile 的这个设定下，完整几何感知通信在 FP8 往返保真度上的收益，几乎全部由输入侧几何单独捕获。

因此我们完全移除输出侧变换，只保留输入侧项。得到的通信坐标可写为

$$\widetilde{W}_{g}=W_{g}T_{A} \tag{22}$$

其中 $T_A$ 是由因子 $A$ 导出的输入侧变换。FP8 量化与通信随后在 $\widetilde{W}_g$ 上执行，同步结果由对应的右侧逆变换映射回欧氏梯度空间。这一简化是使几何感知通信变得实用的第一个关键步骤。

#### V-B 实用简化 II：输入侧几何的低秩近似

一旦完整变换被简化到输入侧，下一个问题是余下的几何必须被多精确地表示。对每个被选中的层都使用完整因子 $A$ 仍然昂贵，因此我们寻求一个成本更低、又能保住大部分通信收益的近似。

设

$$A\approx\mathbb{E}[xx^{\top}],\qquad A\succeq 0 \tag{23}$$

并设

$$A\approx U_{r}\Lambda_{r}U_{r}^{\top} \tag{24}$$

为秩 $r$ 的近似，$r\ll d_\text{in}$。我们从这个降维表示构造输入侧通信变换，并再次用同样的欧氏空间 FP8 往返分析评估所得方法。表 II 报告对比。

**表 II**：输入侧近似的消融，在 FP8 往返后于欧氏梯度空间中评估。低秩近似恢复了完整输入侧变换几乎全部的收益，而秩 32 提供了最好的实际成本—质量权衡。

从表 II 得出两个结论。第一，对角近似相对欧氏基线几乎没有改善，说明**粗糙的逐维缩放不足以捕捉有用的几何**。第二，低秩近似恢复了完整输入侧变换几乎全部的收益。其中秩 32 已经几乎等同于 full-$A$ 的结果，而存储与施加的成本要低得多。我们把秩 32 用作实现的工作点，而**不是**当作一个与模型无关的常数。因此我们在最终实现中采用"仅输入侧 + 低秩 32"作为几何感知变换。

#### V-C 实用简化 III：在脆弱层上选择性部署

即便做了前两项简化，把几何感知通信应用到每一层仍会引入不必要的开销。因此下一个问题是：是否所有层都需要统一地开启几何感知分支？

为回答这个问题，我们在一个 32-GPU、600M 参数 Llama 式模型的预训练过程中 profile 欧氏基线，测量前 100 个训练步内每个 MLP 层（fc1 与 fc2 都算）的数值脆弱度。对每个被 profile 的模块，我们展平其直接参数梯度，计算一个同步的 FP8 scale，把展平梯度编码为 FP8，并统计编码值撞到 FP8 上界与下界的频率。这些边界命中率对 fc1 与 fc2 分别累积，然后在 profiling 窗口上取平均。我们按各层平均上界命中率与下界命中率之和排序，以此作为数值脆弱度打分。

图 3 展示了得到的剖面。脆弱度**高度集中**：在前 13 项之后，打分明显下降，说明最成问题的 FP8 失真被限制在相对少的一部分层里。在这个剖面中，前 13 个脆弱层**全部是 fc2 层**，而第一个 fc1 层紧随这一组之后。因此，13 这个数字并不意味着是一个与模型无关的常数；它是脆弱度排序过程为这个模型与配方选出的工作点。这引出一个简单的选择性部署策略：只对这些被选中的脆弱 MLP 层开启几何感知分支，其余所有层保持欧氏基线。这一策略把额外计算集中在几何感知最可能有帮助的地方，同时为模型的大部分保留了快路径。对于新的模型架构或训练配方，同样的 profiling 过程可以自动重跑以选出层集合。

**图 3**：在欧氏基线下、前 100 个训练步内按平均数值脆弱度对 MLP 层排序。在这个剖面中，前 13 个脆弱层全部是 fc2 层，该组之后可见的下降促成了对这个模型与配方采取选择性部署几何感知分支的做法。

#### V-D 预训练时的流水线

图 4 总结了最终 GIFT 系统在预训练时的结构。所有层共享同一个由量化、通信、反量化构成的通信核心。大多数层以欧氏坐标直接进入这个核心，而被选中的数值脆弱层先施加输入侧低秩变换、之后再把同步结果映射回来。这一组织方式把核心的系统要点讲明白了：**GIFT 不是全局替换欧氏基线，而是只在几何被经验证明有必要的地方增强它。**

**图 4**：GIFT 的预训练时结构。多数层直接以欧氏坐标使用共享通信核心。被选中的数值脆弱层在进入核心前额外施加输入侧低秩变换，之后把同步结果映射回来。

在这个视角下，多数层的默认路径与欧氏基线完全相同。几何感知分支的区别只在于：在共享的 FP8 通信核心之前加一个变换，之后加一个映射回去的步骤。由于该分支只在一小部分层上激活，整个系统在通信结构上仍接近基线，同时纠正了受 FP8 失真影响最大的那些层。

#### V-E 离线准备与预训练时工作流

最终实现由两个阶段组成。第一，我们跑一个离线 profiling 阶段来识别脆弱层集合。第二，在预训练期间，只在被选中的层上激活几何感知分支，其余层继续遵循欧氏基线。被选中的层集合 $\mathcal{S}$ 在预训练之前固定，但输入侧几何因子在训练中**周期性刷新**。在我们的实验中，因子**每 50 个训练步更新一次**。

在当前实现中，层集合 $\mathcal{S}$ 依据上述 profiling 过程在预训练前固定。这一组织方式把层选择逻辑留在主训练循环之外，并为大多数层保留了简单的快路径。算法 1 总结了由此得到的预训练时通信规则。对于被选中的 GIFT 层，我们在变换坐标中使用**局部缩放**，在我们的消融中它比同步一个全局 scale 有更好的经验保真度。

**算法 1**：带输入侧白化与误差反馈的选择性 GIFT 通信

```
 1: 固定的被选中层集合 S
 2: 对每个 l ∈ S，输入侧分解每 K 步更新一次
 3:   A^(l) ≈ L_A^(l) L_A^(l)ᵀ，实验中 K = 50
 4: 误差缓冲 {R^(l)}_{l∈S} 初始化为零
 5: world size N，FP8 量化器 Q(·; s)，缩放规则 Scale(·)
 6: for 每个训练步 do
 7:   for 每个具有权重梯度 W_g^(l) 的层 l do
 8:     if l ∉ S then
 9:       s^(l) ← Scale(W_g^(l))
10:       s^(l) ← AllReduce_MAX(s^(l))
11:       Q^(l) ← Q(W_g^(l); s^(l))
12:       Q̂^(l) ← AllReduce_SUM(Q^(l))
13:       Ŵ_g^(l) ← Dequantize(Q̂^(l); s^(l)) / N
14:     else
15:       U^(l) ← W_g^(l) (L_A^(l))^{-⊤}
16:       Ũ^(l) ← U^(l) + R^(l)                      // 误差反馈
17:       s_loc^(l) ← Scale(Ũ^(l))                   // 局部 scale
18:       Q̃^(l) ← Q(Ũ^(l); s_loc^(l))
19:       Ũ_deq^(l) ← Dequantize(Q̃^(l); s_loc^(l))
20:       R^(l) ← Ũ^(l) − Ũ_deq^(l)                  // 残差留在变换坐标里
21:       s_comm^(l) ← s_loc^(l)
22:       if 这是一个 scale 同步步 then
23:         s_comm^(l) ← AllReduce_MAX(s_loc^(l))
24:       end if
25:       Q̂^(l) ← AllReduce_SUM(Q̃^(l))
26:       Û^(l) ← Dequantize(Q̂^(l); s_comm^(l)) / N
27:       Ŵ_g^(l) ← Û^(l) L_A^(l)ᵀ                    // 映射回欧氏坐标
28:     end if
29:   end for
30:   优化器用 {Ŵ_g^(l)} 更新参数
31: end for
```

有两个实现细节值得强调。第一，几何感知分支只在一个固定的、被选中的层子集上激活，因此模型的大部分遵循原始欧氏路径，不做额外的几何处理。第二，几何感知分支**在变换坐标中使用误差反馈**，使量化残差被累积在通信实际发生的地方。这让实现与通信公式保持一致，而不是把误差反馈当作一个事后的独立修正。

#### V-F 实现小结

我们的最终实现是通过对 §IV 完整几何感知公式的逐步简化得到的。我们先在观察到输入侧几何捕获了完整设计几乎全部实际收益之后移除输出侧变换，然后用秩 32 的低秩近似压缩余下的输入侧几何，最后只在一小部分数值脆弱层上部署所得变换。

这些简化产生了一个实用的混合系统：欧氏仍是默认通信路径，几何只在经验上有理由的地方被引入。因此，实现在通信结构与代价上都接近基线，同时在最需要的那些层上恢复了完整几何感知通信所测得的大部分保真度收益。

### VI. 实验结果 (Experimental Results)

我们从四个互补的角度评估 GIFT。第一，随着模型规模与 GPU 数增长，测量低精度通信的系统收益。第二，检验 GIFT 是否在验证损失意义上保持了预训练行为。第三，比较下游任务性能，判断几何感知通信是否比直接欧氏通信更好地保住了有用的模型质量。第四，考察 GIFT 相对直接欧氏基线的显存开销。

我们的目标**不是**声称 GIFT 在每个指标上都一致改善。目标是检验一个更具体的假设：**在相同的低精度通信格式下，只改变通信坐标就能提升被通信更新的有用性。** 这个区分在我们的设定中很重要，因为优化损失与下游任务质量并不总是给出相同的方法排序。

#### VI-A 实验设置

我们在 OpenWebText 上研究两个 LLaMA 风格的预训练配置。第一个是约 300M 参数、序列长度 4096 的模型。第二个是约 600M 参数、序列长度 2048 的模型。我们使用不同的序列长度是为了塞进 GPU 显存。

除非另有说明，所有端到端预训练实验使用 **32 张 GPU**、global batch size 512、micro batch size 4、**Muon 优化器**、学习率 $5\times10^{-4}$、cosine decay、最小学习率 $5\times10^{-5}$。

所有实验都在德州先进计算中心（TACC）的 Vista 超级计算机上进行。Vista 包含 600 个基于 NVIDIA GH200 Grace Hopper Superchip 架构的 Grace Hopper 计算节点，**每个 Grace Hopper 节点提供一张带 96 GB HBM3 显存的 NVIDIA GPU**，以及一颗通过紧耦合 CPU–GPU 设计互联的 NVIDIA Grace CPU。

对于端到端预训练，我们比较三种实用方法：

- **FP32**：全精度梯度通信。
- **欧氏基线**：在欧氏参数坐标中直接做 layer-wise FP8 通信。
- **GIFT**：最终的实用几何感知设计，只在收益足以抵消代价的地方施加几何感知分支，其余保持欧氏基线路径。

我们基于额外的 600M 实验在每一类中选择更强的基线。BF16 梯度通信在 14 个下游任务中有 7 个匹配 FP32，但其绝对任务数值整体略低，因此我们用 FP32 作为高精度参考。对于欧氏 FP8，block size 512 的标准 per-block 缩放在 14 个下游任务中只有 4 个匹配 FP32，差于 layer-wise 欧氏基线；因此我们在主对比中使用更强的 layer-wise 欧氏 FP8 基线。

#### VI-B 低精度通信的规模收益

我们首先考察随规模增长时低精度通信的系统收益。图 5 报告了欧氏基线与 GIFT 相对 FP32 基线的 step-time 改善随 GPU 数的变化，覆盖 300M 与 600M 两个模型。正值表示该方法比 FP32 快，负值表示更慢。

我们观察到三个趋势。第一，低精度通信的通信优势在更大规模下更明显，尤其对 600M 模型。第二，更大的模型从通信成本的下降中更一致地获益，这是符合预期的，因为在更大规模下通信占端到端 step time 的比例更大。第三，**GIFT 仍然慢于直接欧氏基线**，因为它引入了额外的几何感知计算，但它仍保留了低精度系统相对 FP32 收益中相当大的一部分。最重要的是，随着 GPU 数增加，这个差距在拉大，而这正是通信效率最要紧的区间。

这些结果表明，低精度通信对更大规模下的更大模型更有效，从而为一个"用可控的额外计算换取更好的模型质量保持"的几何感知方法留出了空间。

**图 5**：相对 FP32 通信的 step-time 改善随 GPU 数的变化。正值表示比 FP32 基线快，负值表示更慢。低精度通信的相对收益在更大的 GPU 数下更明显，尤其对 600M 模型。GIFT 由于额外的几何感知计算而慢于直接欧氏基线，但它保留了相对 FP32 的通信侧加速中相当大的一部分。

#### VI-C 预训练中的验证损失

接下来我们通过验证损失考察预训练行为。图 6 对两个模型规模比较 FP32、欧氏基线与 GIFT。

主要观察是：GIFT 与欧氏基线在两个模型规模上都表现出**非常相似的验证损失轨迹**。两种低精度方法在整个预训练过程中都与 FP32 基线保持合理接近，但 GIFT 与欧氏基线之间在验证损失上的差距很小。

这一点对解读其余结果很重要。验证损失是一个有用的优化层面信号，但我们的方法改变的是通信保真度，而不是模型架构或目标函数。在这种设定下，验证损失上的细微差异并不必然意味着下游模型性能的退化。因此，我们把验证损失视为有信息量但**不完整**的度量，并把下游评估作为决定性检验。

**图 6**：300M 模型（上）与 600M 模型（下）预训练期间的验证损失，比较 FP32、直接欧氏基线通信与 GIFT。两种情况下 GIFT 与欧氏基线的验证损失曲线都非常相似，两者都与 FP32 基线保持合理接近。这也凸显了一个更广的要点：验证损失只是预训练质量的一个局部代理，通信方法之间的差异可能在下游性能上比在预训练损失上更明显。

#### VI-D 下游任务性能

现在我们转向本文的主要实际问题：哪种方法在端到端预训练之后更好地保住了有用的模型质量？

表 III 报告所有被评估方法的下游结果。每一列对应一个下游任务，最右列汇总相对 FP32 的任务胜场数。我们逐任务呈现结果，因为主要问题不只是整体性能，还包括每种通信方法在不同下游评估上**保持有用模型质量的一致性**。

下游结果比验证损失曲线揭示出更清晰的区分。对 300M 模型，欧氏基线在 14 个任务中的 4 个上优于 FP32，而 GIFT 在 7 个上优于 FP32。我们还在 300M 模型上评估了完整 K-FAC 变体。尽管完整 K-FAC 使用了更完备的几何感知状态，它在 14 个任务中的 6 个上优于 FP32，仍差于最终的选择性 GIFT 设计。这支持了我们的设计选择：选择性地施加几何感知，能比到处使用更重的完整 K-FAC 式分支保住更多有用的下游行为。

对 600M 模型，欧氏基线在 14 个任务中的 5 个上优于 FP32，而 GIFT 再次在 7 个上优于 FP32。我们另外报告了 600M 的 BF16 与 per-block 欧氏 FP8 消融。BF16 在 14 个任务中的 7 个上匹配 FP32，但其绝对任务数值整体略低，因此 FP32 仍是更强的高精度参考。Per-block 欧氏 FP8 只在 4 个任务上匹配 FP32，差于 layer-wise 欧氏基线。因此，主要的欧氏对比使用更强的 layer-wise FP8 基线而非较弱的 per-block 变体。

因此，尽管所有方法在验证损失上都相对接近，GIFT 在两个模型规模上都给出了比直接欧氏基线更有利的下游剖面，并且在 300M 消融中也优于更重的完整 K-FAC 变体。

这些结果不应被解读为 GIFT 在每个任务上都匹配 FP32。它们表明的是：**GIFT 相对直接欧氏 FP8 通信改善了跨任务的保持剖面。** 通信压缩的目的不只是让损失曲线在视觉上接近 FP32，而是保住同步更新的有用性。我们的结果表明，在激进的低精度通信下，几何感知通信更好地保护了与任务相关的预训练信号。换言之，改变通信坐标改善了相对欧氏基线的下游保持剖面，即使这一改善在验证损失上只有微弱体现。

#### VI-E 显存研究

我们比较 GIFT 与直接欧氏基线的显存占用。对 300M 模型，GIFT 使显存使用增加约 **3.33%**。对 600M 模型，增加约 **8.98%**。这一开销主要来自被选中层所存储的输入侧低秩因子与变换坐标下的误差反馈缓冲。由于几何分支是选择性的，开销保持有限，而不是像完整双侧逐层 K-FAC 状态那样扩张。总体而言，这些结果表明几何感知设计对这两个模型只引入了适度的显存开销。

#### VI-F 讨论

实验支持三个主要结论。

第一，低精度通信的系统收益随规模增长而变大。这对更高 GPU 数下的 600M 模型尤其清楚，此时通信占整体 step time 的比例更大。

第二，GIFT 与直接欧氏基线在两个模型规模上都与 FP32 在验证损失上保持合理接近，同时彼此的损失轨迹也非常相似。这说明验证损失对"通信质量如何影响最终模型性能"是一个有信息量但不完整的代理。

第三，也是最重要的，下游评估表明几何感知通信比直接欧氏基线通信更好地保住了模型质量。在两个模型上，GIFT 都取得了比欧氏基线更有利的下游保持剖面，尽管它并非在每个单项任务上都更好。300M 的完整 K-FAC 消融以及 600M 的 BF16 与 per-block 欧氏消融进一步支持了最终对比设定的选择：完整 K-FAC 不优于选择性设计，BF16 不是比 FP32 更强的参考，per-block 欧氏 FP8 弱于 layer-wise 欧氏基线。这意味着，如果评估只限于损失曲线，GIFT 的主要收益会被低估。

综合来看，这些结果支持本文的核心主张：**改变通信坐标能使低精度梯度通信比直接欧氏 FP8 更忠实于高精度参考，并且通过选择性部署，这可以在实用的系统代价内实现。** 尽管我们的实验聚焦 FP8，GIFT 背后的坐标变换原理并不是 FP8 专有的，这意味着一旦硬件与软件支持成熟，同样的思想可以应用于未来的 FP4 通信。

#### VI-G 局限性

我们当前的评估有若干局限。第一，端到端实验聚焦于两个中等规模的 Llama 模型与一个固定的预训练配方。测试更大的模型、更长的训练周期与更广的硬件区间会很有价值。第二，尽管下游结果已经显示 GIFT 相对直接欧氏基线的一致优势，若增加更多随机种子与更大的评测套件，评估会更有说服力。第三，本工作专门关注**仅通信**的低精度通信，而非完全量化的预训练栈。未来工作可以研究，当与更广的低精度预训练配方结合时，同样的几何感知原理是否仍然有用。

即便有这些局限，当前结果已经确立了主要的实际要点：相对直接欧氏 FP8，几何感知通信提升了在 FP8 梯度通信下所保留的质量，同时保住了使低精度通信具有吸引力的那部分通信侧效率。

### VII. 结论 (Conclusion)

本文从几何感知的视角研究 LLM 预训练的低精度梯度通信。我们的出发点是这样一个观察：低精度通信误差不仅是一个数值格式问题，也是一个**坐标系问题**——在各向异性的梯度几何下，在欧氏坐标中直接量化会给聚合后的更新引入可观的失真。受此启发，我们基于 K-FAC 式的二阶结构给出了完整的几何感知通信规则，并把它逐步简化为实用的系统实现。我们的结果表明，完整双侧公式所测得的 FP8 往返保真度收益，绝大部分可以由一个便宜得多的混合设计恢复：只保留输入侧几何、用 32 秩表示近似它、并选择性地应用到数值上最脆弱的层。由此得到的 GIFT 系统为模型的大部分保留了欧氏基线快路径，同时改善了低精度通信的保真度—开销权衡。GIFT 在 64 张 NVIDIA GH200 Superchip 上为 Llama-600M 预训练带来 **7.6%** 的时间改善，同时相对直接欧氏 FP8 通信改善了下游保持剖面。随着通信压力随模型规模与 GPU 规模持续增长，几何感知通信对未来更低比特的 LLM 预训练系统可能会变得越来越有用。

我们希望这一视角能鼓励在高效分布式 LLM 预训练中对"通信感知的几何方法"做进一步研究。

## 五、对 MI455X / Helios 的参考点

> 前提：Helios / MI455X（CDNA5），432 GB HBM4/GPU，**单 scale-up 域 72 GPU**，per-GPU scale-up 3.6 TB/s（UALink-over-Ethernet），机架 scale-up 聚合 260 TB/s，per-GPU scale-out **约 597 GB/s**（scale-up : scale-out ≈ **6:1**）。
> 当前的具体缺口：NVIDIA 在 Megatron-LM 里的 **GTP（Generalized Tensor Parallelism）** 已经把权重 all-gather 压到原生 MXFP8/NVFP4，但**权重梯度的 reduce-scatter 仍然是 BF16**，于是 RS 占到 per-weight 通信预算的 **64–78%**。我们要拿下低精度 wgrad reduce-scatter。
> （算一下就知道这个占比是对的：AG 走 NVFP4 且只做一次 = 0.5|W| 字节，RS 走 BF16 = 2|W| 字节，RS 占 80%；AG 走 FP8 且前反向各一次 = 2|W|，RS 占 50%。64–78% 正落在这个区间里。）

### 5.1 GIFT 能不能用在 reduce-scatter 上

**论文本身没测过。** Algorithm 1 从头到尾是 `AllReduce_MAX` 与 `AllReduce_SUM`，实验是 32 GPU 纯 DP，没有分片优化器、没有 ZeRO、没有 TP。所以这是我们要自己回答的问题。

**结构上的答案是"能，而且 RS 比 all-reduce 更合适"**，理由是变换的形状：$\widetilde{W}_g = W_g T_A$ 是对梯度矩阵的**右乘**，$T_A \in \mathbb{R}^{d_\text{in}\times d_\text{in}}$。右乘沿 $d_\text{in}$ 混合，**逐行独立**：$(W_g T_A)[i,:] = W_g[i,:]\cdot T_A$。因此

- 任何沿 $d_\text{out}$（行）的分片在这个变换下是**封闭的**。RS 之前在完整本地梯度上做变换，RS 之后只在收到的那个 row-band 上做映射回去，**不需要任何额外 collective**。
- 而且比 all-reduce 更省：map-back 只作用在 $1/N$ 的行上，而 all-reduce 要在全量上做。

**但有三个必须先解决的前提，全部是论文没碰到的：**

**(1) 分片边界必须按行对齐。** Megatron 的 distributed optimizer 与 FSDP2 都是把多个参数打进一个 flat buffer、**按字节等分**给各 rank。一个 shard 可以从某一行的中间开始、跨过参数边界。这会破坏 map-back 的局部性。需要在 `ParamAndGradBuffer` 的 bucket 布局里加**行粒度对齐（padding）**。工作量有界——FP8 block scaling 本来就需要类似的对齐约束，可以合并做。

**(2) 所有 rank 必须用同一个 $T_A$，而论文没说 $A$ 怎么跨 rank 一致。** 这不是细节而是正确性问题：若各 rank 用本地数据估的 $A^{(r)}$，则 $\sum_r W_g^{(r)} T_A^{(r)} \neq \big(\sum_r W_g^{(r)}\big) T_A$，映射回去就是错的。实现上必须在每次刷新时对 $A$（或其 rank-32 因子 $U_r$）做一次 all-reduce/broadcast。代价很小（$d_\text{in}\times 32$），但**必须显式做**，否则是一个安静的数值错误而不是崩溃。

**(3) TP 下 GIFT 选中的层恰好最麻烦 —— 而论文从未遇到。** GIFT 的脆弱层前 13 名**全是 fc2**，而 fc2 在 Megatron 里是 row-parallel 线性层，它的 $d_\text{in}$（= ffn_hidden）**正是被 TP 切开的那一维**。右乘要跨完整 $d_\text{in}$ 混合，本地做不了。

  好消息是低秩形式给了一个便宜的出路。写 $T_A = I - U_r M U_r^\top$（$M$ 是 $32\times32$），则

  $$W_g T_A = W_g - (W_g U_r)\,M\,U_r^\top$$

  其中 $S = W_g U_r = \sum_t W_g^{(t)} U_r^{(t)}$ 只需要对一个 $[d_\text{out}, 32]$ 的 sketch 做一次 TP all-reduce，之后的修正项完全本地。额外流量 $= 32/d_\text{in}$ 倍的权重大小，$d_\text{in}=8192$ 时约 **0.4%**，完全可接受。**代价是在梯度路径上插了一次 TP collective，必须和别的东西 overlap，否则它落在关键路径上。**

**(4) 顺带一个必须修的语义问题。** Algorithm 1 第 17–26 行让各 rank 用**自己的** $s_\text{loc}$ 量化，然后对 FP8 码 `AllReduce_SUM`，再用单一 scale 反量化。各 rank scale 不同时这在数学上不一致。做 RS 时要么强制同步 MAX scale（欧氏分支的做法），要么走 ZeRO++ qgZ / SDP4Bit 那种**分层 all-to-all + 本地高精度归约**的路子——后者顺带绕开了"环形归约里反复重量化"的误差累积问题，在 72 卡域上尤其值得考虑。

### 5.2 ROCm 兼容性：纯数学，没有任何 NVIDIA 专属原语

**方法层面完全无关厂商。** GIFT 的全部内容是：两个瘦 GEMM + 周期性的 top-32 特征分解 + 逐元素量化/反量化 + 误差反馈缓冲。它**不碰 GEMM 路径**（这一点与 `mxfp4-pretraining.md` 那条线完全不同），不需要 Transformer Engine、不需要 NVFP4 block scaling、不需要任何 tensor-core 的格式技巧。它作用在 backward 与 collective 之间的梯度张量上，是纯张量代数。

**collective 侧也不是障碍。** RCCL 已经原生支持 `ncclFloat8e4m3` / `ncclFloat8e5m2`，并且 reduce-scatter 在支持列表里。两个要在真机上验的点：

- RCCL 的 FP8 归约路径是否**真的调优过**，还是会掉进慢速 fallback。这是半天的 rccl-tests 就能回答的问题，应该最先做。
- **编码差异**：CDNA3（MI300X/MI325X）原生支持的是 **FNUZ** 变体，CDNA4+（MI355X/MI455X）支持 **OCP** 变体。作为**通信载荷格式**，这个差异是跨代互操作的真实隐患——而 roadmap 里明确记着客户会混部 MI300X/MI325X/MI355X。**在 wire format 契约里把编码显式钉死**，不要依赖默认。

**ROCm 侧真正的 kernel 工作，以及它为什么值得做：**

1. **一个融合 kernel，这是全部价值所在。** 先算个账：变换的 flops 是每个选中层 $4\,d_\text{out} d_\text{in} r$，而该层前反向是 $6 B d_\text{out} d_\text{in}$，比值 $= 2r/(3B_\text{tokens})$，$r=32$、$B=8192$ 时约 **0.03%**。**算力上这是免费的。** 那 GIFT 那 3.19 个百分点的开销从哪来？来自 HBM 往返：误差反馈要读一遍 $R$、写一遍 $R$，变换要读写梯度，量化再读写一遍——朴素实现是 4–5 次全量往返。所以要做的 Primus-Turbo kernel 是**把「EF 累加 → 低秩变换 → amax → 量化」融成一遍**，梯度只读一次、只写一次。**结论：GIFT 的开销是实现产物，不是本质开销**，融合之后应该能贴近直接 FP8 的 10.79%。这也顺带解释了为什么在带宽受限的 MoE expert GEMM 场景下要格外小心——小矩阵上访存开销摊不开。
2. **周期性的 top-32 分解**，50 步一次，不在热路径上。关键实现要点是**不要物化 $A$**：$d_\text{in}=28672$ 时 $A$ 是 3.3 GB，直接不可行。用随机化 range finder，只算 $A U \approx a(a^\top U)$，中间量是 $[\text{tokens}, 32]$。论文在 600M 上没暴露这个问题（$d_\text{in}$ 才 4096 量级），**放到真实宽度上这是第一个会炸的地方**。
3. **不需要为 GIFT 写 Hadamard kernel。** 但注意 ROCm TE 里已经有确定性 Hadamard（MXFP4 那条线留下的），它是"几何无关"的廉价对照组——见 §5.4，这个对照必须做。
4. **显存**：GIFT 在 600M 上的 +8.98% 主要是选中层的**全精度误差反馈缓冲**，规模上是 $O(4 \times |W_\text{sel}|)$ 字节，随选中层参数量线性增长。432 GB HBM4 让绝对量可以承受，但它直接和 72 卡 scale-up 域本该买来的激活预算竞争。§5.3 的分层设计能把这块降到 $1/k$。

### 5.3 在 72 卡 scale-up 域上，这是不是该花算力换带宽的地方

**方向对，论文的数字不对，而真正可操作的结论在放置策略上。**

**方向为什么对。** Helios 上 DP 梯度归约走的是 597 GB/s 的 scale-out 路径，比 3.6 TB/s 的 scale-up 窄约 6 倍。从这条管子上省下的每一个字节，都是从全系统最稀缺的资源上省下来的；而 CDNA5 的算力是过剩的那一侧。用算力换这条带宽，交易方向是对的。

**为什么 7.6% 不会迁移过来 —— 三条，每条都指向"论文的拓扑是最有利的极端"：**

1. **Vista 是每节点一张 GPU**（论文原文写明）。**它根本没有 scale-up 域**，100% 的 DP 梯度流量都走机间网络。这是现存最有利于通信压缩的拓扑。Helios 上凡是落在 72 卡域内的那部分 DP 归约，本质上是免费的。
2. **几乎没有梯度累积。** global batch 512 / micro batch 4 / 32 GPU，每步最多 4 个 micro-batch。生产 global batch 下 DP 归约被摊到多得多的 micro-batch 上，它在 step time 里的占比会显著下降。
3. **基线是 FP32 而不是 BF16。** 按 §2.4(c) 的推导，相对 BF16 基线，直接 FP8 只有约 **+3.9%**，GIFT 约 **+0.4%**——而且这还是上界。

**真正可操作的那一条：wgrad 压缩划不划算，取决于 DP 组有没有机架内的一段。**

- **放置 A：TP×EP×PP = 72 填满机架，DP 纯跨机架。** 此时 100% 的 wgrad RS 都在窄管上，压缩的收益最大——但你也要在**每个 rank 的完整梯度**上付变换算力和误差反馈显存。收益和代价同时最大化。**注意这大概率就是默认配置**：按 [`mi455x-parallelism-strategy-reference.md`](../knowledge/systems/mi455x-parallelism-strategy-reference.md) 里 NVL72 的规范映射（`TP1 PP4 EP64`，EP 完整落在域内），域被 EP/PP 填满，DP 自然全部落到跨机架侧。
- **放置 B：TP×EP×PP = 8–18，每机架 4–9 个 DP rank。** 做两级归约：**机架内 RS 走 BF16、3.6 TB/s，基本免费；只对跨机架那一段的 $1/k$ 分片做变换 + 量化。** 这样**变换算力和误差反馈显存同时降到 $1/k$**，而省下的字节仍然全部落在窄管上。
- 这正是 **SDP4Bit 已经在用的结构**（节点内 8-bit / 节点间 4-bit），也就是说这个设计不是我们发明的，是已经被 6.7B/18B 验证过、且有开源实现的。
- **所以这条对当前的并行策略选型是一个真实的输入：优先选留给 DP 一段机架内路径的放置。** 它不只是带宽账，它决定了低精度 wgrad 压缩到底便宜还是昂贵。

**净判断**：这是**对的地方**，但**不是对的第一步**。第一步是先量出 wgrad RS 在我们目标放置下到底占多少 step time（见 §5.6 P0）。如果在高 GA + 放置 B 下它只占 3%，那整条线的天花板就是 3%，应该让位给 C3-5 的 all-gather 侧。

### 5.4 与 `papers/mxfp4-pretraining.md` 的交叉检验

这是最需要认真对待的一条。[`mxfp4-pretraining.md`](./mxfp4-pretraining.md) 在 MI355X 原生 MXFP4 上的核心发现是：**随机舍入与随机 Hadamard 在全流水下都不收敛，确定性 Hadamard 把 token 开销打回 8–9%**；而且这个对照是干净的（随机 H16 与确定性 H16 同尺寸，一个不收敛一个能救），所以被隔离出来的有害变量是**随机化本身**，不是旋转尺寸。

GIFT 也用旋转类变换。那么这条发现是支持还是威胁 GIFT？**答案是三段的，而且第三段是最有价值的。**

**(a) 首先，这是两个战场，不能直接搬结论。**

| | MXFP4 论文 | GIFT |
|---|---|---|
| 量化对象 | **GEMM 操作数**（Fprop/Dgrad/Wgrad 的输入） | **通信载荷**（DP 梯度） |
| 误差进入频率 | 每个 micro-step 的每个 matmul | 每个优化器步一次，进入的是**已平均**的梯度 |
| 抵消位置 | 在 matmul 内部（$HH^\top = I$） | 在 collective 两侧 |
| 误差被后续放大的路径 | 直接进前向/反向数值流 | 只进优化器输入 |

误差进入频率差了好几个数量级。所以 MXFP4 的结论不是对 GIFT 的直接判决。

**(b) 在"随机 vs 确定"这条轴上，MXFP4 的发现是支持 GIFT 的。**

MXFP4 隔离出的有害变量是随机化。而 **GIFT 的变换是完全确定的**：$L_A$ 来自 $A = \mathbb{E}[aa^\top]$，Algorithm 1 里没有随机符号翻转、没有随机舍入、没有任何随机源。它站在 MXFP4 研究认定为安全的那一侧。

更进一步，可以把 GIFT 看成确定性 Hadamard 的**一个泛化**：Hadamard 是数据无关的正交旋转，把能量均匀摊开；GIFT 的白化是数据相关的变换，按实测输入协方差摊。如果"确定 + 数据无关"能救，那"确定 + 数据感知"在保真度层面先验地至少一样好——Table II 也确实证实了（RelL2 5.28e-2 → 1.72e-2，而这是 Hadamard 类方法拿不到的，因为 diag-A 那一行说明有用的几何是跨维耦合的）。

**(c) 但 MXFP4 的发现指出了 GIFT 一个具体的威胁，论文完全没有讨论：GIFT 不是静态确定的，它每 50 步换一次坐标系。**

MXFP4 论文对"随机化为什么有害"的解释是：随机方法**只是加噪声**，并不治理 outlier 驱动的 micro-scaling 误差。也就是说，有害的是**注入到量化几何里的非平稳性**。而 GIFT 每 $K=50$ 步刷新一次 $L_A$。每次刷新时：

- 欧氏坐标下的量化噪声协方差从 $\propto A_\text{old}$ 跳到 $\propto A_\text{new}$。这是有效噪声几何的一次**不连续跳变**——一个温和的、周期性的版本，但性质上正是 MXFP4 研究认定为有害的那种非平稳性。
- **更具体、也更严重的一条：误差反馈缓冲 $R^{(l)}$ 是累积在变换坐标里的**（Algorithm 1 第 16、20 行）。刷新 $L_A$ 时，$R$ 里那份陈旧的残差是用**旧基**表示的，却被加到用**新基**表示的梯度上（第 16 行），然后用**新的** $L_A^\top$ 映射回欧氏坐标（第 27 行）。**这是一个基不匹配**，会注入一个正比于 $(L_A^\text{new} - L_A^\text{old})^\top R$ 的伪更新。论文一个字都没提。在 300M–600M、短 horizon 下它大概率永远不会显形；在 10 万步以上、$A$ 条件数更大的规模上，这恰恰是那种慢性、无声的发散来源——也正是 MXFP4 那条线踩过的坑的形状。
- **另一条独立的风险：$L_A^{-\top}$ 的求逆没有给阻尼。** 各向异性是本文的前提，$A$ 天然病态；rank-32 近似让它严格奇异。Eq. (9) 只写了"regularized K-FAC factors"，**正则化强度全文没有出现**。欠阻尼的白化会无界地放大低曲率方向——这比 MXFP4 论文里的任何机制都更可能在大规模下炸掉。

**移植时必须带的三条修正**（都很便宜）：

1. **刷新时对 $R$ 做基变换**（$R \leftarrow R\,L_{A,\text{old}}^\top L_{A,\text{new}}^{-\top}$）**或直接清零**。清零更安全，代价是丢掉 50 步的残差累积。
2. **warmup 之后冻结 $L_A$**，让坐标系变成完全静态。**这是与 MXFP4 发现最一致的选项**——它把 GIFT 变成一个确定性静态旋转，也就是在 MI355X 上被证明能收敛的那个配置。代价是失去对训练中几何漂移的适应，但论文完全没有证据表明这种适应是必要的（它从没做过"冻结 vs 刷新"的消融）。
3. **阻尼系数是移植时第一个要扫的超参**，不是可选项。

**净结论**：MXFP4 的发现**支持 GIFT 的方向**（确定优于随机），同时**精确指出了 GIFT 最可能的失效模式**（时变坐标 + 陈旧误差反馈 + 无阻尼求逆）。两者不矛盾——按上面三条移植，它们是一致的；不按，我们就是在重蹈那条已经踩过的坑。

**顺带一个反向的收获**：MXFP4 论文说确定性 Hadamard 能把 Wgrad 的 FP4 开销完全消掉。既然 ROCm TE 里已经有这个 kernel，那么**"确定性 Hadamard + FP8 wgrad RS"是一个比 GIFT 便宜得多的对照组**：数据无关、无需维护二阶统计、无需跨 rank 一致、无需阻尼、坐标系天然静态。它捕获不到 GIFT 那 67% 里跨维耦合的部分，但它把 GIFT 的四个工程负担一次性全部消掉。**这个对照必须在上 GIFT 之前做完。**

### 5.5 与 Muon / DistMuon 线的关系

**先纠正一个预期：这篇论文并没有真的分析 Muon。** Muon 出现在两个地方——实验设置里的优化器选择，以及引言里用来和 FP8-LM/COAT 的"AdamW 专用"做区分。**全文没有 Muon vs AdamW 的对照，没有任何关于量化误差如何与 Newton-Schulz 交互的分析。** 不要把这篇当作关于 Muon 的证据引用。

**但论文放在桌上没捡的那个机制，恰好是我们这条线最该测的：**

Muon 的 NS 迭代把梯度矩阵的奇异谱**压平**（$G = U\Sigma V^\top \to UV^\top$），因此它会**放大**落在小奇异值方向上的任何噪声。

- 欧氏 layer-wise FP8 用**一个** scale，各方向的**绝对**噪声大致均匀 ⟹ **相对**噪声在小奇异值方向上最糟 ⟹ 而那正是 NS 放大最狠的地方。
- GIFT 的白化让噪声在白化坐标里各向同性，即在欧氏坐标里协方差 $\propto A$ ⟹ 高激活方差方向上绝对噪声更大，而那也正是梯度主奇异方向所在（$G = \sum \delta a^\top$）⟹ **相对**误差被均衡了，而这恰是 NS 这种尺度不变算子想要的。

**如果这个机制是真的，那么低精度梯度通信在 Muon 下应该明显比在 AdamW 下更脆弱，而 GIFT 式白化在 Muon 下的收益应该更大。** 这是一个干净、便宜、没人做过的实验，而且直接落在 L102 / L250（layer-wise distributed Muon）上。**这是 GIFT 本该产出而没有产出的那个结果，我们有条件补上。**

**与 owner placement 的组合出乎意料地干净。** 在 [DMuon](./dmuon.md) / [MatrixFSDP](./matrixfsdp.md) 的 owner placement 下，完整的梯度矩阵**整块**落在单个 owner rank 上。这**直接消除了 §5.1 的全部分片问题**——map-back 天然本地，不需要行对齐，不需要 TP sketch collective。同时要注意两者的层次不同：MatrixFSDP/DMuon 消掉的是**优化器步**的矩阵通信，GIFT 压缩的是**梯度归约**这个 collective，两者正交、可叠加。而且 owner placement 里"把完整矩阵送到 owner"的那次归约，正是 GIFT 要压缩的那一次。

### 5.6 建议先做什么，以及工作量

**顺序很重要，而论文自己的数字就在论证"先做简单的那个"**：直接欧氏 FP8 比 GIFT **快**（10.79% vs 7.6%），而 GIFT 的质量优势经不起复核（§2.4）。**不要从 GIFT 开始。**

另外一个前置判断：**SDP4Bit 是比 GIFT 好得多的起点** —— 对的 collective（ShardedDP = RS + AG）、对的框架（Megatron-LM）、开源、做到 6.7B/18B、而且它的两级结构正是 §5.3 的放置 B 设计。GIFT 相对它的增量只是"坐标系"这一个想法，应该被当作**可选的后期精化**，而不是地基。

**P0 —— 先量清楚问题有多大（约 1 人周）**

在写任何 kernel 之前，在 MI355X 上的真实 Primus 跑里量两件事：

1. **DP wgrad reduce-scatter 在我们为 Helios 考虑的放置下、在真实 GA 下，到底占多少 step time。** 如果低于约 5%，整条线的天花板就是两三个百分点，应该降优先级、把人放到 C3-5 的 all-gather 侧。
2. **把 GIFT 的脆弱度 profiler 抄过来跑一遍。** 这是全文最可复用、成本最低的东西，而且和它的几何主张解耦：前 100 步逐层统计 FP8 边界命中率。它回答的是"**我们的**模型（dense 和 MoE 都要跑）敏感度是不是也集中在少数几层、是不是也是 fc2"，而不是 600M Llama 的答案。**如果集中性不成立，选择性部署的成本论证就整个塌了**，GIFT 也就没有意义了。

另加半天：用 rccl-tests 确认 RCCL 的 FP8 reduce-scatter 走的是调优路径而非 fallback，并把 OCP/FNUZ 编码在 wire format 里钉死。

**P1 —— 直接做 BF16 → FP8 的 wgrad reduce-scatter，不带几何变换（约 2–3 人周）**

这才是 GTP 真正的缺口，也是 80% 的价值所在。内容：per-shard scale + 同步 MAX、**欧氏坐标下的误差反馈**、落在 Megatron distributed optimizer / Primus 的 buffer 路径里；如果放置给了 DP 机架内的一段，直接做成两级。在我们真正在乎的模型上测质量。

**必须补上论文省掉的那个消融：欧氏 + 误差反馈。** GIFT 分支有 EF 而它的欧氏基线没有，所以论文的头条对比把"换坐标系"和"加误差反馈"混在了一起。**很有可能 plain FP8 + EF 就把整个差距填平了**——那样我们就到此为止，而且比 GIFT 更快。

**P2 —— 只有当 P1 显示出真实质量差距时，才加几何变换（约 3–4 人周）**

仅输入侧 rank-32（数据显示 rank-16 就够，先试 16）；**warmup 后冻结坐标系**（§5.4）；阻尼系数扫参；刷新时 EF 重定基或清零；用随机化 range finder 避免物化 $A$；实现成**一个融合的 Primus-Turbo kernel**（EF 累加 → 变换 → amax → 量化），梯度只读一次。论文那 3.19 个百分点是 HBM 流量不是 flops，融合之后应该基本消失。

**并且在这之前先做 §5.4 那个更便宜的对照：确定性 Hadamard + FP8 wgrad RS。** 它没有 GIFT 的四个工程负担（二阶统计、跨 rank 一致、病态求逆、时变坐标），ROCm TE 里 kernel 已经有了。如果它拿到 GIFT 收益的大部分，GIFT 就不用做了。

**P3 —— 机会性，可与 P1 并行（约 1 人周）：Muon vs AdamW 的低精度梯度通信敏感度对照**

同模型、同配方，FP8 wgrad RS 开/关，Muon vs AdamW 各一组。便宜，而且是 GIFT 本该产出的那个 Muon 专属结果。直接喂给 L102 / L250。

**合计约 2 人月**，而且 P0 / P1 无论 GIFT 这个具体机制成不成立都是有用的——它们产出的是"我们自己的脆弱度剖面"和"能用的 FP8 wgrad RS"，这两样东西不依赖任何一篇论文的结论。
