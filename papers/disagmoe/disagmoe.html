DisagMoE:注意力-FFN 解耦的 AF-Pipe 计算通信重叠训练

arXiv 2026-05 ByteDance Seed + UW + Cornell 16×8 H800

论文: arXiv:2605.11005
英文题名: DisagMoE: Computation-Communication overlapped MoE Training via Disaggregated AF-Pipe Parallelism
笔记路径: slab/papers/disagmoe/README.md
TL;DR 把 attention 与 FFN 拆到不相交 GPU 组(A-Worker DP、F-Worker EP),用 AF-Pipe 多阶段流水把 all-to-all 变 many-to-many(M2N/N2M)并当作一等流水阶段与两侧计算 overlap(通信 ↓1/k、bubble ≈ baseline 1/4),再用 compute-comm roofline + MILP 自适应给两组分 GPU/NIC。核心洞察:attention FLOPs 随 seq 二次、FFN+comm 线性 → 结构性失衡,对称加带宽推不动。up to 1.81× vs Megatron-1F1B / 1.34× vs Tutel/Comet/DualPipe。

1. 问题

Large-EP 下 dispatch/combine 两次 all-to-all 卡关键路径,64×H800 通信占 up to 50%(8 节点 all-to-all 占比 78%)。op 级 chunk overlap(Tutel/Comet)窗口被 FFN 上界卡 + FlashAttention 难切 → 留尾巴;micro-batch pipeline(DualPipe)面临 attention 二次/FFN 线性的结构性失衡;serving AFD 与 HeterMoE 训练场景 OOM(仅 ~4.3B)。

2. 核心方法

  • 解耦放置: 组件类型切层,A-Worker 组内 DP、F-Worker 组内 EP,每组可持多层 → 显存约束下支持更大 MoE。
  • AF-Pipe: 时分复用流水(fwd hidden A→F、bwd 梯度 F→A);all-to-all → M2N/N2M 当一等流水阶段 overlap,融 P2P+combine 通信 ↓1/k,warm-up bubble ≈ baseline 1/4;异步 forward/backward/comm 三流。
  • 自适应资源分配: roofline + MILP 分 GPU/NIC——① GPU split 最小化瓶颈阶段消 bubble ② NIC split 最大化 MFU(抬 slack 侧 compute roof);MILP seed + profile 精调。

4. 与 monolith-moe / rocmoe 的对照(重点)

互补的两条路:我们在单节点把 attention+MoE 融进 super-kernel,它把 attention/FFN 拆到不同组。但它的 roofline 洞察对我们有用。

DisagMoE我们关系
attention 二次/FFN+comm 线性 → 结构性失衡只在 MoE 层内 overlap⭐ 佐证 attention 不该占通信预算
roofline + MILP 分 GPU/NICcomm_ratio 单 knob 纯 sweep⭐ 可用 roofline 判据先验定 comm_ratio 再精调
跨节点 IB 带宽是主约束单节点 XGMI 带宽充裕他们收益主要来自带宽稀缺;我们 overlap 上限更低(见 R 判据)

结论

  • attention/FFN compute-comm 比结构性失衡:佐证我们只做 MoE 层内 overlap 是对的,attention 是 compute-bound 不该占通信预算。
  • roofline+MILP 定资源划分 比纯 sweep comm_ratio 更有原则,可先算先验点再局部精调。
  • 其收益主要来自跨节点 IB 带宽稀缺,单节点 XGMI 带宽充裕时 overlap 绝对上限受 bw/peak 比制约(与 MegaScale-MoE R 判据一致)。

5. 局限

  • 假设 pretraining 固定形状,动态形状(RL)需在线重分配;单一 pipeline 深度共用。
  • 6K Python + 2K C++,基于 Megatron-LM,M2N 用 GPUDirect+GPUCopy。
