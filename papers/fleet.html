Fleet: 面向多芯粒 GPU 的分层任务抽象与 Megakernel

arXiv AMD Research MI350X LLM Decode

论文: arXiv:2604.15379 · PDF
英文题名: Fleet: Hierarchical Task-based Abstraction for Megakernels on Multi-Die GPUs
笔记路径: slab/papers/fleet.md
TL;DR Chiplet GPU 把 L2 切成 8 份，但 HIP 仍按「整卡统一 L2」编程，导致 LLM decode 权重在 XCD 间重复进 HBM。 Fleet 新增 Chiplet-task（绑定一个 XCD + 协作读权重），在 Mirage 式 persistent megakernel 里用 per-chiplet 调度与 M-major tiling 抬高 L2 命中。 MI350X + Qwen3-8B：相对 vLLM（eager）小 batch 约 1.3–1.5× 更快；bs=64 时 L2 命中率 39%→61%，HBM 读降 37%，但大 batch 仍输给 hipBLASLt K-split。

1. 问题背景

MI300/MI350 等采用 8 个 XCD，每个 XCD 有 私有 4 MB L2（共 32 MB），再加 256 MB Infinity Cache 与 HBM。 默认全局 load 在 wave scope 下只在本地 XCD 的 L2 缓存，不同 XCD 不共享、不自动失效 _peer 上的副本。 若调度把读同一 weight 行的 workgroup 散到多个 XCD，同一权重会从 HBM/LLC 拉多遍。

LLM decode 以内存带宽为主：Qwen3-8B 单层权重约 368 MB（bf16），线性层约占 decode 时间 95%。 传统服务栈每层多次 kernel launch（约 250 次/token/36 层），kernel 间 device barrier 会 刷掉 L2，无法跨算子复用权重。

2. 核心思想：四层任务 + Chiplet-task

Wavefront-task  →  单 wave（SiLU、residual、RoPE）
CU-task         →  单 workgroup（RMSNorm、单头 attention）
Chiplet-task    →  单 XCD 上全部 worker（GEMM 列分区 + L2 协作）  ← 新增
Device-task     →  8 个 Chiplet-task 完成一整颗算子

运行时：整卡一个 persistent kernel；每 XCD 1 个 scheduler workgroup（占 8/256 CU），其余为 worker。 Chiplet-task 由 scheduler 广播 到同 XCD 所有 worker；CU-task 在 XCD 内 round-robin。 事件依赖用 两级计数：XCD 内 L2-local 原子，仅每 XCD 最后一个 worker 做 buffer_wbl2 + 全局事件更新。

3. Chiplet 感知 GEMM

  • N-split： 输出列均分 8 份，每 XCD 算 [M, N/8]，K 维完整归约，无需跨 XCD 同步。
  • M-major 窗口遍历： 同 XCD 内多 worker 先共享同一 weight 列（M-tile），再换列；避免 N-major 导致并发读不同列。
  • M-split 消融： 每 XCD 不同 M-tile、无 weight 共享，用于分离「仅调度优化」与「L2 协作」。
  • Cache 策略： 权重 load 用 streaming（sc1=1, nt=1）；activation 写 NT bypass L2；跨 XCD 事件轮询用 NT load。
  • 融合： SiLU 并入 gate+up Chiplet-task，减少中间 buffer 的 L2 写回。

理论 L2 权重命中率：(R-1)/R，R = min(W, m_tiles)，W=每 XCD worker 数（31），m_tiles = ⌈B/T_M⌉。

6. 局限与我们工作的启示

论文局限

  • 单模型、单卡 MI350；无 TP 多卡、prefill、MoE。
  • 对比 vLLM 使用 enforce-eager，可能低估 graph 路径。
  • 代码未公开；大 batch 需 K-split 与 attention 优化。

对我们（MI355 / megakernel / MoE）的启示

  • 把 chiplet 当 机内 NUMA：显式 XCD 亲和 + L2 驻留权重与 MonolithEP/RocMoE 方向一致。
  • 做 persistent fused kernel 时应预留 Chiplet-task 粒度 与 两级 fence，避免默认 HIP 调度打散 L2。
  • benchmark 应用 M-split 式消融区分 调度 vs L2 协作；报告 rocprofiler L2/HBM。
  • 与 Mirage/Primus MPK 路线互补：Mirage 决定 fuse 什么，Fleet 决定 在哪个 XCD 上跑。
