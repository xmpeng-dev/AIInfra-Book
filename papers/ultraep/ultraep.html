UltraEP:Rack-Scale 节点上的实时精确负载均衡

arXiv 2026-06 北大 + 小红书 + 上海 AI Lab Rack-Scale Node AMD Helios / NVIDIA Rubin up to 256 GPU

论文: arXiv:2606.04101
英文题名: UltraEP: Unleash MoE Training and Inference on Rack-Scale Nodes with Near-Optimal Load Balancing
笔记路径: slab/papers/ultraep/README.md
TL;DR 首个在 RSN(64+ GPU scale-up 域)上对 large-EP MoE 做 exact-load、实时(每 microbatch+每层) 负载均衡的系统。既有 EPLB/LPLB 靠历史预测追不上非平稳负载;UltraEP 在 gating 后拿真实负载,用 quota-driven planner(联合 replication+reroute,GPU-native 单 CTA/SM 求解 ~0.1ms)+ RSN-native 通信(persistent tile streaming + chunk relay 树)。inter-rank 不均 1.30–4.01 → 1.01–1.04,达 94.6% 训练 / 93.9% serving 理想吞吐,训练 1.42× vs Megatron、serving 1.56× vs SGLang。

1. 问题

Large-EP 放大专家负载不均 → 计算 straggler + all-to-all 瓶颈 + 激活显存尖峰。EPLB/LPLB 靠历史预测周期性重排,但前沿细粒度 MoE 专家热度在 microbatch/层/数据域间剧烈漂移,stale 预测常失效甚至加剧不均。转 exact load 需在 gating 后才拿到 → 均衡被逼上关键路径。RSN 把 scale-up 域扩到整机架 64+ GPU,使热路径均衡第一次物理可行。

2. 核心方法

  • Replication-only + 跨层 buffer 复用: 不重排 main expert;redundant slot 不存 optimizer state、跨层共享 buffer,Qwen3-235B 单 slot 3.3GB→36MB。
  • Quota-driven planner: 二分负载阈值 τ + 贪心可行性 oracle,用 quota 当耦合变量同时选 replica 并预留 reroute 容量(只创建有效 replica);GPU-native 单 CTA/SM + shared memory + warp 归约。
  • Reroute: 本地 token 优先消费本地 quota 省跨 rank 流量,残余按比例分 + 确定性 rounding。
  • RSN-native 通信: persistent tile streaming(double-buffer,任务查找/寻址折进流水)+ 热 expert(replica>4)建 chunk-streaming relay 树(frontier≈√fan-out,load-aware 选发送量最小 rank 当 relay)。
  • 反向:恢复 redundant weight(与 Wgrad overlap)+ 每 main expert 聚合 replica 梯度回 main buffer(保训练等价)。

4. 与 monolith-moe / rocmoe 的对照(重点)

平台高度对口:显式点名 AMD Helios RSN,而我们正是单节点 8×MI355X / XGMI(一个小型 scale-up 域)。它解决我们一直回避的负载不均正交轴。

UltraEP我们关系
exact-load 实时均衡固定 round-robin 分 WG,假设 token 均匀⭐⭐ 直击 A2 失败根因(token 不均致 tile 利用率坍塌)
quota 联合 replication+reroute,GPU-native(单 CTA/SM,~0.1ms)暂无系统级均衡⭐ 可在 super-kernel 内塞一个 planning phase
persistent tile streaming + chunk relay 树persistent super-kernel + receiver-pull通信同源;relay 树是我们没做的 fan-out 分摊
RSN scale-up 域内均衡才可行我们本就在 XGMI scale-up 域内⭐ 天然满足前提

三条最有用的结论

  • 负载不均要在系统层解——正是我们 A1/A2「动 compute 排布无效」的互补答案:不要让排布吸收不均,而应在 dispatch 前按 exact load 分 quota / 迁 token。
  • quota-driven GPU-native 求解(单 CTA/SM,~0.1ms)证明热路径做均衡决策可行,super-kernel 可塞类似 planning phase。
  • 我们天然满足 RSN 前提(XGMI),UltraEP 点名 AMD Helios,是 rocmoe 引入负载均衡时的首选参考。

5. 局限

  • 强依赖 RSN scale-up 域,标准 RDMA 集群(EP 跨节点走 scale-out)不适用。
  • 9.6K 行 C++/Python,集成 Megatron-LM + SGLang,用 DeepEP hybrid-ep 分支。
