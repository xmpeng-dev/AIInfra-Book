TL;DR 首次把 MegaKernel 用到 MoE 训练:把 Dispatch+GroupGEMM 与 GroupGEMM+Combine 各融成一个持久化单 kernel(1 threadblock / SM),SM 动态分 Comm/Comp/Relay 三角色、token 级 scoreboard 同步、单 CUDA stream 内 overlap;靠确定性 token 映射(AllGather 计数 + rank 维 prefix-sum 全局 offset)保 bit-wise 与串行一致。Relay 做 rank 内 multicast 省 ~34% 流量,10^5 空间解析 autotuner(C++ 144ms)。vs COMET 1.03–1.38× 端到端 / kernel 级最高 18.4× vs 非重叠。
⭐ 与本项目最紧密的一篇。 UniEP 基本是 Hopper 侧版本的 RocMoE-v2 super-kernel:MegaKernel + SM 角色分配 + 片上 scoreboard + 单 stream + 确定性排序,逐条能对上我们的设计(见最后一节)。

1. 问题

MoE 的 dispatch+expert+combine 吃掉训练 30%–80% 时间。现有 overlap 两大缺陷:① 多流粗粒度 overlap 需 host 同步 + 产生 bubble,且切 micro-batch 改变反向累加顺序 → 破坏 bit-wise 可复现;② 缺统一通信原语(top-k 大用 AllGather、稀疏用 AllToAll),逼开发者维护多套 kernel。

2. 核心方法

  • 持久化 worker + 三角色: 线程块数 = SM 数常驻;Comm(putmem push)/Comp(padding-free GroupGEMM)/Relay(信号 + rank 内 multicast)。动态角色:全局 atomic 任务队列,SM 取任务定角色,初始全通信、数据到齐转计算,天然均衡。
  • 确定性 token 映射(保 bit-wise): 用 AllGather 的每-rank-每-expert 计数 + 沿 rank 维 exclusive prefix-sum 算全局写偏移,叠本地 stable-sort → 无锁无冲突唯一地址,token 到达顺序固定 → 反向 Transposed GroupGEMM 累加树不变。
  • Scoreboard: [S_token | S_tile],Relay 攒够一 tile 置位,Comp 就绪即算,ld_acquire/st_release 保序。
  • Relay multicast: 一 token 多 expert 落同 rank 只传一次 + 本地复制,Top-8/8GPU → 平均 5.25 unique rank,−34% 流量。
  • AutoTuner: 10^5 配置(N_disp/N_comb/N_relay/N_red/warps),解析 roofline 模型,C++ 144ms + 分桶缓存;预测误差均值 3.8%。

4. 与 monolith-moe / rocmoe 的对照(重点)

目前和 RocMoE-v2 super-kernel 最同源的一篇,几乎逐条对得上:

UniEP我们关系
持久化 worker + 动态 Comm/Comp/Relay 角色super-kernel + comm_ratio + __launch_bounds__(_,1) 隔离 CU同源;他们动态分角色,我们 build-time kSubWGs 静态 → ⭐ 可动态化
确定性 token 映射(prefix-sum 全局 offset)保 bit-wisecounting-sort + atomicAdd 写 pack_perm(非确定序)⭐⭐ 最该借鉴:正好解掉 backward 与 pack_perm 的强耦合
token 级 scoreboard + release/acquire64-bit block_ready 位图收敛一致
Relay intra-rank multicast(−34% 流量)暂无⭐ 新点:DSV3 top_k=8/EP8 同样可省 XGMI
push(putmem) > get 实测receiver-pull(比 push 慢 ~43%,靠 overlap 藏)⚠️ 反向结论,值得在 MI355X XGMI 复测 pull vs push

三条最有用的结论

  • 确定性 token 映射是我们 backward pack_perm 耦合的现成解:AllGather 计数 + rank prefix-sum 得确定 offset,替掉非确定 atomicAdd。列为 rocmoe 高优先级实验。
  • 动态 SM 角色 + 解析 autotuner 比 build-time kSubWGs 更能吸收 skew(hot_cov50 下 dispatch 变 critical path)。
  • Relay multicast 是正交省流量招;UniEP 已开源 Triton 实现且明确可移植 AMD,可直接读 Triton-distributed 代码对照。

5. 局限

  • Triton 实现,最新架构上可能弱于手写 CUDA(称可重写 CUDA 补齐);未用 TMA;评测限单节点 8 GPU。
  • 代码开源(~21k 行 Python),作者称可移植 AMD。
