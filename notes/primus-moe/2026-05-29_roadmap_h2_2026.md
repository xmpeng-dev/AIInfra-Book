# [ROADMAP][2026 H2] Primus MoE Roadmap

> Draft mirroring the format of [`NVIDIA/Megatron-LM#4815`](https://github.com/NVIDIA/Megatron-LM/issues/4815).
> Scope: **Primus-LM** (training framework) + **Primus-Turbo** (operator layer) on AMD GPUs.
> Hardware focus: **MI300X / MI325X (gfx942)** and **MI350X / MI355X (gfx950)**.
> Cadence: 2026 Q3 + Q4. Subject to change as the dev branch evolves.

- **⚠️ Roadmap tracks the dev branches of [Primus-LM](https://github.com/AMD-AGI/Primus) and [Primus-Turbo](https://github.com/AMD-AGI/Primus-Turbo).**
- **Companion blogs:** [Primus-MoE Package](https://rocm.blogs.amd.com/software-tools-optimization/primus-moe-package/README.html) · [Efficient MoE Pre-training on 1K AMD GPUs with TorchTitan](https://pytorch.org/blog/efficient-moe-pre-training-at-scale-with-torchtitan/)
- Previous roadmap reference: Primus-Turbo H1 2026 Roadmap → [Primus-Turbo#211](https://github.com/AMD-AGI/Primus-Turbo/issues/211)

# Primus MoE — Supported Features (current)

### Model Support

- **DeepSeek**
  - DeepSeek-V2 (lite/16B/236B), DeepSeek-V3 (671B) — BF16 + FP8 pretrain, MTP under upstream Megatron
- **Qwen**
  - Qwen2.5 (3B / 7B / 14B / 32B / 72B), Qwen3 (4B / 8B / 14B / 32B), Qwen3-MoE (30B-A3B, 235B-A22B) — BF16 + FP8 pretrain
- **Llama4 MoE**
  - Llama4 17B-16E and Llama4 17B-128E — BF16 + FP8 pretrain (Megatron + TorchTitan)
- **Mixtral**
  - Mixtral-8x7B v0.1, Mixtral-8x22B v0.1 — BF16 + FP8 pretrain
- **GPT-OSS**
  - GPT-OSS 20B and 120B — BF16 + FP8 pretrain (MI355X)
- **Other MoE families**
  - Grok1 / Grok2, Kimi-K2, GLM5, Minimax-M2.5, LFM2-8B-A1B — BF16 + FP8 pretrain

### Backends

- **Megatron-LM** — primary training backend; full Mcore-MoE feature surface patched into Primus
- **TorchTitan** — DeepSeek-V3 (16B/236B/671B), Qwen3, Llama4 MoE
- **JAX MaxText** — Mixtral-8x7B and Llama family (MoE coverage subset)

### Core MoE Functionality (already in)

- ✅ **Token-dropless MoE** with Top-K routing
- ✅ **Auxiliary load-balancing loss** (sigmoid + group-topk routing for DeepSeek-V3)
- ✅ **GroupedGEMM** (BF16 + FP8) via Primus-Turbo `grouped_gemm` / `grouped_gemm_fp8`
- ✅ **Permute / Unpermute** fused kernels (`primus_turbo.pytorch.ops.moe`)
- ✅ **Token dispatcher** (`primus_turbo.pytorch.modules.moe.token_dispatcher`)
- ✅ **FP8 All-to-All** (`primus_turbo.pytorch.dist.fp8_alltoall`)
- ✅ **DeepEP (experimental)** on AMD via rocSHMEM (training kernels only, MI300 series)
- ✅ **Async-TP** comm-compute overlap primitive (`primus_turbo.pytorch.ops.async_tp`)

### Advanced Parallelism (already in)

- ✅ **Expert Parallel (EP)** integrated with DP / TP / PP / SP / CP for the Megatron path
- ✅ **Distributed Optimizer for MoE** (Megatron + TorchTitan FSDP variants)
- ✅ **Megatron Parallel Folding** patched through (heterogeneous parallel mappings)
- ✅ **HSDP / FSDP for MoE** on TorchTitan with expert sharding

### Optimizations (already in)

- ✅ **HipBLASLt autotuning** wired into Primus runtime; cached per-shape per-arch
- ✅ **AITER fused MoE / FlashAttention** kernels selectable at module level
- ✅ **Composable Kernel (CK) GEMM** for FP8 / BF16 grouped paths
- ✅ **Distributed checkpointing** (Megatron mcore + TorchTitan DCP)
- ✅ **Fine-grained activation recompute** for MoE / norm / attention

### Precision Support (already in)

- ✅ **BF16** end-to-end across all listed models
- ✅ **FP8 (E4M3 / E5M2)** training for DeepSeek-V3, Mixtral, Qwen3-MoE, Llama4, GPT-OSS
- ✅ **GroupedGEMM FP8** with per-token / per-channel scaling

### Developer Experience (already in)

- ✅ **Primus CLI 1.0** — unified entry for local / container / Slurm
- ✅ **Preflight cluster sanity checker** (per-node GPU / NIC / RCCL diagnostics)
- ✅ **Benchmark suite** for MoE end-to-end and per-kernel measurement
- ✅ **Layer-wise loss / grad-norm logging**
- ✅ **HuggingFace ↔ Megatron / TorchTitan checkpoint converters** for the supported families

### Hardware Differentiation Already Landed

- Tile-level **comm–compute super-kernel** prototype (RocMoE / MonolithEP research lines, 8× MI355X) — used as roofline reference for the production Primus path.
- **Persistent dispatcher** that hides A2A inside FC1 GroupedGEMM on MI355X (Layout-P + receiver-pull).
- **XGMI-aware peer-pull dispatch** primitives in Primus-Turbo (`ipc_primitives` family).

# 2026 H2 Roadmap (Q3 + Q4)

## Model Supports

### DeepSeek-V4 / DeepSeek-V3.x

#### Functionality

- Architecture parity with Mcore upstream
  - **mHC (manifold hyper connection)** support — port from `Megatron-LM#2943`
  - **sqrtsoftplus router score function** — port from `Megatron-LM#4193`
  - **DSA (DeepSeek Sparse Attention)** support — port from `Megatron-LM#2440`
  - **Hybrid Attention with CSA + HCA**
  - **Hash MoE + ClampedSwiGLU + mHC contract**
  - **MTP with mHC**
- Muon support
  - Newton-Schulz coefficient bump for DeepSeek-V4 schedule
  - **Layer-wise distributed Muon optimizer** integration
  - **FP8 primary weights for Muon**
  - Precision-aware optimizer state on AMD ROCm
- Packed sequence
  - **DSv4 hybrid-attention THD support**
  - **Dispatcher THD support** (Primus-Turbo `token_dispatcher` extension)
- Long context
  - **DSv4 hybrid-attention CP support** (Megatron + TorchTitan)
- Convergence verification
  - **HF ↔ MCore checkpoint conversion** for V4 family
  - **E2E loss-parity verification** vs reference (NVIDIA H100 / B200)

#### Performance Optimization on AMD

- mHC kernels
  - **mHC fusion kernels in CK / Triton** on gfx942 + gfx950
  - **mHC + EP comm overlap**
- Hybrid Attention
  - **Fused dense MQA kernel** for AMD (AITER backend)
  - **Fused CSA / HCA kernel** for AMD
  - **FP8 indexer compute** in Primus-Turbo
- ClampedSwiGLU
  - **Fused ClampedSwiGLU** in Primus-Turbo (CK + Triton variants)
  - Plumb through Megatron and TorchTitan MoE blocks
- **batched-GEMM fusion + FP8** in `grouped_gemm_fp8` (variable-K and variable-M paths)

#### E2E Training Recipes

- 4K dense training (DSv3-Lite scale)
- 16K sparse training (DSv3 671B scale on 1k+ MI300X / MI355X)
- 64K sparse training (long-context recipe)

#### Long-Term Topics

- Anticipatory routing
- Flexible activation checkpointing for hybrid attention
- **MegaMoE-style speculative routing** prototype on AMD

### Qwen3.5 / Qwen3-Next

#### Functionality

- **Qwen3.5 / Qwen3-Next functionality** parity with Mcore
- **Packed sequence (THD) support**
- **HF ↔ Mcore / TorchTitan checkpoint conversion**

#### Performance Optimization

- Gated Delta Rule (GDN) optimization on AMD
  - **GDN kernel fusion on gfx950** (CK / AITER backends)
  - **GDN + FlashQLA integration** through Primus-Turbo `attention`
  - **Pre-gated delta rule kernel fusion** (conv1d + memory ops)
- General perf
  - **Full-iteration HIP graph capture** to amortize host overhead in MoE
  - **Gated RMSNorm in Primus-Turbo `normalization`**
- Memory optimization
  - **GDN fine-grained activation offloading** (P0.5)
  - **GDN selective recompute** (in_proj / conv1d / gated_delta_rule) (P1)

#### Long-Context Training

- **GDN context parallel in A2A / Ulysses mode**
- **GDN context parallel in AllGather mode** — enables Qwen3.5-397B with > 64K seq-len
- **Dynamic CP for multimodal training**

#### Multimodal Training (Qwen3.5-VL)

- **OOTB E2E FSDP example** for THD-format Qwen3.5-VL on TorchTitan
- **Dynamic CP** for vision encoder
- **Heterogeneous parallelism** for encoder–decoder split

### Other models on AMD

- **Kimi-K2 v2** (sparse + RL recipes)
- **GLM-5 v2 / Minimax-M3** as upstream releases hit dev branch
- **Llama4-Maverick** post-train recipe (RLHF + DPO on AMD)

## Core MoE Functionality

### Routing

- **Comm-aware Top-K router** (research line, see `slab/knowledge/moe/research-overview.md` direction A)
  - Add a comm-cost penalty term to the gate score; λ schedule with annealing
  - First target: cross-node A2A traffic reduction on 1k-GPU MI355X clusters
- **Router-replay for RL** (parity with Mcore `feat: add routing replay #2693`)
- **Sparse mixture sub-types** (Hash MoE, MoE-ECHO sync-free dropless) in Primus paths

### Load Balance / Fault Tolerance

- **MoE ECHO** — sync-free, full-CUDA-graph dropless MoE port (HIP graph + RCCL group launch)
- **Expert hot-swap** for 1k+ GPU runs (works with Primus-SaFE topology layer)

## Advanced Parallelism

### Expert Parallel

- **DeepEP v2 token dispatcher** integration in Primus-Turbo (rocSHMEM + IBGDA path)
- **HybridEP for AMD** — XGMI intra-node + RDMA inter-node split, mirroring NV HybridEP for GB200
- **NCCL-EP / RCCL-EP** support for fallbacks where DeepEP is not viable
- **1F1B EP A2A overlap** schedule on Megatron path (port of NV `1F1B EP A2A Overlap`)

### Tensor / Context / Pipeline

- **Async-TP for MoE attention path** (extend `primus_turbo.pytorch.ops.async_tp`)
- **Dynamic CP** for imbalanced long-sequence training (Megatron + TorchTitan)
- **Dynamic CP + HIP graph** for low-overhead long-context iterations

### FSDP / HSDP

- **Megatron-FSDP for MoE on AMD** with full expert-parallel support
- **FSDP + A2A overlap** (port of `Megatron-LM#3796`)
- **TorchTitan FSDP MoE perf optimization** for DSv3 / Llama4 / Qwen3-MoE

### AMD-Specific Parallelism Research → Primus

- **AMD-FSEP** — fully-sharded expert parallel on AMD using XGMI direct read instead of explicit ReduceScatter (research line C)
- **MoE-Native IR** — comm-aware compile-time scheduling (research line B), prototype as a Primus optional path
- **Backward comm scheduling** — split dX / dW computation, fully overlap dW AllReduce (research line D)

## Optimizations

### Memory

- **Memory-efficient permute / unpermute** (extend Primus-Turbo `moe_permute`)
- **Pipeline-aware fine-grained activation offloading** for MoE (port of `Megatron-LM#1912`)
- **Fine-grained recompute** knobs (mla / moe / mlp / moe_act / norm / attention)
- **Paged stashing** for dropless MoE under HIP graph (port of `Megatron-LM#2690`)

### Communication

- **DeepEP on AMD productionization** — parity with H100 / B200 numbers, IBGDA path
- **HybridEP fusion with permutation** (port of NV permute/unpermute fusion + dispatch/combine)
- **1F1B EP A2A overlap** on Mcore path
- **DP / PP / TP / EP comm overlap** unified scheduler in Primus runtime
- **Token-level chunked A2A** with Primus-Turbo for variable-load experts

### Computation

- **Fused router** (top-k + softmax + bias + group-topk) — Triton + CK
- **MLA RoPE fusion** (FP8-aware) — port from upstream TE
- **Permutation fusion** — already in, extend to FP8 / MXFP8
- **Production-ready HIP graph for MoE** — capture full step incl. comm
- **GEMM + SwiGLU fused MLP** (port of `Megatron-LM#3890`) for non-MoE branch
- **GroupedGEMM gradient-accumulation fusion** in Primus-Turbo
- **MoE super-kernel productionization** — graduate the RocMoE / MonolithEP research super-kernel into a Primus-Turbo `super_moe` op behind a feature flag (target: BF16 wall ≤ 7 ms on DSv3 T_src=2048 / 8× MI355X; FP8 wall ≤ 5 ms)

### Optimizer

- **Muon** + **layer-wise distributed optimizer** for AMD
- **CPU-offload optimizer state** with HIP-aware staging
- **Precision-aware optimizer** (FP8 weights with BF16 / FP32 master)

## Precision Support

- ✅ **BF16 / FP16 / FP8** GroupedGEMM already supported
- 🚀 **MXFP8 GroupedGEMM** — Primus-Turbo MXFP8 path on gfx950 (block-scaled E4M3 / E5M2)
- 🚀 **FP8 weights with BF16 / FP32 optimizer states** — full e2e for DSv3 / Qwen3-MoE
- 🚀 **MXFP4 / NVFP4-equivalent training** exploration on gfx950 (research / enablement)
- 🚀 **FP8 router / FP8 indexer** for DeepSeek-DSA family

## Developer Experience

- **Primus MoE Model Zoo** — analogue of Megatron MoE Model Zoo, with reference recipes per model × precision × hardware
- **MCore ↔ HF / SafeTensors converter** in `primus-bridge` (single CLI for all supported MoE families)
- **HIP graph + distributed checkpointing** integration (resume mid-graph)
- **Runtime upcycling** — initialize a sparse MoE from a dense Llama / Qwen checkpoint
- **Layer-wise logging UX** — Grafana / W&B dashboards bundled with Primus
- **Preflight expansion** — MoE-specific sanity checks (router stats, A2A bandwidth, DeepEP rocSHMEM smoke)

# H1 2026 Highlights (already shipped or in flight)

### Performance & Kernel Optimizations

- **MoE Super-Kernel research line (RocMoE)** — 8× MI355X persistent grid with Layout-P + receiver-pull, BF16 dispatch wall reduced from 9.41 ms → 4.22 ms (2.23×) on DSv3-prod T=8192; tile-level comm–compute overlap validated.
- **MonolithEP MoE production line** — 4.82 ms / 8× MI355X, Primus DSv3 e2e converged with loss parity vs Megatron baseline.
- **mfma_tile.h GEMM** — 1290 TFLOPS / GPU on `8192×4096×7168` (≈ 99 % MI355X BF16 peak).
- **HipBLASLt autotuning** wired into the Primus runtime (cache-aware, per-arch).
- **Async-TP for AMD** in Primus-Turbo.

### Long Context & Context Parallel

- **CP integration** through Megatron + TorchTitan paths
- **THD format** end-to-end exploration on TorchTitan

### Model & Architecture

- **DeepSeek-V3 671B** end-to-end on Primus / TorchTitan (FP8 + BF16)
- **Llama4 17B-128E**, **GPT-OSS 120B**, **Qwen3-235B-A22B** added to MI355X config matrix
- **Kimi-K2**, **GLM-5**, **Minimax-M2.5**, **LFM2-8B-A1B** brought up

### Advanced Functionality

- **DeepEP (experimental)** on ROCm via rocSHMEM, training kernels
- **FP8 All-to-All** in Primus-Turbo
- **GroupedGEMM FP8** with hipBLASLt + CK backends

### Cluster & Stability

- **Preflight** cluster sanity checker
- **Primus CLI 1.0** unified interface
- **Topology-aware scheduling** through Primus-SaFE
